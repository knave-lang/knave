`knave fmt` lays out the code in docstrings: an example paragraph, which holds a
line that starts with `=> `, and a fence whose info string is empty or `knave`.
This warning reports such code that does not read as forms. An unclosed list does not read, nor does code of another
language in an untagged fence, nor code nested past the reader's limit of 1,024
lists. A result that spans several lines also fails when a later line sits no
deeper than its code, because that line would read as new code.

Only `knave fmt` reports it, with or without `--check`, in every docstring:
those of definitions, `document` and `module`. The formatter keeps the code as
written and lays out the rest of the file. The warning does not change the exit
status.

## Erroneous example

```knave
;; knave fmt
;; project.knv
(defproject pairs)
;; src/main.knv
(defn pairs (x)
  "Pairs a number.

  (pairs 1)
  => (vec 1
  1)"
  (vec x x))
```

## Fixes

Indent each later line of a result deeper than its code:

```knave
;; knave fmt
;; project.knv
(defproject pairs)
;; src/main.knv
(defn pairs (x)
  "Pairs a number.

  (pairs 1)
  => (vec 1
       1)"
  (vec x x))
```
