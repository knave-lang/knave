A variant or struct pattern whose parts have no labels matches the fields of
the payload in order, one part for each field. This error reports such a
pattern whose count of parts differs from the count of fields, such as
`(rect w)` for a variant with two fields, `(point x)` for a variant with none,
or `(some a b)`. It covers patterns with or without the enum's name, struct
patterns, and payloads whose fields have names. A pattern with labels, such as
`(rect :w w)`, may leave fields out, and `(point)` matches a variant with no
payload.

A pattern of a variant of an enum that the compiler refused, such as an enum
whose type parameter no payload uses, can report this error after the error
that refused the enum.

## Erroneous example

```lisp
(defenum shape (rect f64 f64) point)

(type area (fn (shape) f64))

(defn area (s)
  (match s
    ((rect w) w)
    (point 0.0)))

(defn main () (println (area (shape/rect 1.0 2.0))))
```

## Fixes

Bind each field:

```lisp
(defenum shape (rect f64 f64) point)

(type area (fn (shape) f64))

(defn area (s)
  (match s
    ((rect w h) (* w h))
    (point 0.0)))

(defn main () (println (area (shape/rect 1.0 2.0))))
```

Or write `_` for a field the arm does not use:

```lisp
(defenum shape (rect f64 f64) point)

(type width (fn (shape) f64))

(defn width (s)
  (match s
    ((rect w _) w)
    (point 0.0)))

(defn main () (println (width (shape/rect 1.0 2.0))))
```
