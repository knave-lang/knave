Each top-level definition becomes a Rust item, and the compiler derives the
item's Rust name from the definition's name. A function takes snake case, so `-`
turns into `_`, a trailing `?` turns into an `is_` prefix and a trailing `!`
drops. A `def` of another value takes upper snake case, and a struct or an enum
takes camel case, with a `2` suffix when that name is a name of Rust's prelude
such as `Clone`. This error reports two definitions of one file, both reached
from `main`, whose Rust names are the same, whatever kinds they are.

Such pairs include the functions `a-b` and `a_b`, `empty?` and `is-empty`, or
`bump!` and `bump`, the values `limit` and `LIMIT`, the structs `point-2d` and
`point2d` or `Clone` and `clone2`, a struct `color` beside an enum `Color`, and
a function `Point` beside a struct `point`. A struct or an enum also reports it
when a `rust-type` that the program uses has a template that starts with the
same Rust name, such as a struct `flag` beside `(rust-type marker "Flag")`.

A definition that `main` never reaches reports nothing, and neither do two
definitions in different modules. A definition that a macro introduced takes a
numbered Rust name instead of reporting this error, and so does a definition
whose Rust name would be `main`, such as a function `main!`. Parameters and
other local names never report this error. Two struct fields or two enum
variants with one Rust name do not report it either.

## Erroneous example

```lisp
(defn empty? (n) (= n 0))

(defn is-empty (text) (= (len text) 0))

(defn main () (println (empty? 0) (is-empty "")))
```

## Fixes

Spell the text check `blank?`, whose Rust name is `is_blank`:

```lisp
(defn empty? (n) (= n 0))

(defn blank? (text) (= (len text) 0))

(defn main () (println (empty? 0) (blank? "")))
```

Or drop the text check, and compare the length where the program needs it:

```lisp
(defn empty? (n) (= n 0))

(defn main () (println (empty? 0) (= (len "") 0)))
```
