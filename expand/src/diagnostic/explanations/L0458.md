knave writes an `iterator` in Rust as `impl Iterator<Item = ...>`. This error
reports a type that knave writes with `impl`, such as an `iterator` or a
`rust-type` whose template starts with `impl `, anywhere in the type of a struct
field or an enum payload, including inside another type, as in `(option
(iterator i64))`. It also reports one inside a function type in a parameter or
result of a top-level function, whether a `type` signature writes it or
inference finds it, as for `counter` in `(defn tally (counter years) (counter
(iter years)))`, and one inside a function type in the signature of a method of
a program's own `trait`, whether or not the program calls the method. A closure
bound by `let` reports it at a parameter that holds such a type when the
closure's body calls a method, such as `count`, on that parameter.

A top-level function whose parameter or result is the iterator itself reports
nothing, and neither does a closure bound by `let` that passes its iterator
parameter to a function. This error does not stop the ownership checks, so a
program whose only type errors are this one also reports its ownership errors.

## Erroneous example

```knave
(defstruct feed
  :items (iterator i64)
  :label str)

(defn main ()
  (let (years (->feed :items (range 2019 2025) :label "years"))
    (println (:label years))))
```

## Fixes

Keep a vector in the field:

```knave
(defstruct feed
  :items (vec i64)
  :label str)

(defn main ()
  (let (years (->feed :items (vec 2019 2020 2021) :label "years"))
    (println (:label years))
    (println (count (iter (:items years))))))
```
