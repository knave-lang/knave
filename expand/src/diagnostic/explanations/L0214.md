`recur` starts the enclosing function again with new arguments, so nothing may
wait for its result. Its place is the value of the body, a branch of an `if` or
a `match` in that place, or the last form of a `do` or a `let` there. This error
reports a `recur` anywhere else, such as an argument of a call, as in `(+ n
(recur (- n 1)))`, a form before the last one of a body, the value of a `local`,
or the test of an `if`. A `recur` inside a `loop` follows the same rule within
the loop's body. `deftest` adds a form after its body, so a `recur` written
directly in a test body is never in tail position.

## Erroneous example

```lisp
(defn sum-to (n)
  (if (= n 0)
    0
    (+ n (recur (- n 1)))))

(defn main ()
  (println (sum-to 4)))
```

## Fixes

Carry the running total as a parameter, so `recur` is the whole branch:

```lisp
(defn sum-to (n total)
  (if (= n 0)
    total
    (recur (- n 1) (+ total n))))

(defn main ()
  (println (sum-to 4 0)))
```

Plain recursion may sit inside a call:

```lisp
(defn sum-to (n)
  (if (= n 0)
    0
    (+ n (sum-to (- n 1)))))

(defn main ()
  (println (sum-to 4)))
```
