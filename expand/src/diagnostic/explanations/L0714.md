A library from a git repository names the repository with `:git` and the commit
to build with `:rev`, so that every build of the program reads the same files.
This error reports a library entry with `:git` and no `:rev`. A branch or a tag
can move to another commit, and `:rev` takes neither.

The compiler reports each such mistake in the file, not only the first. Every
command that reads the project reports it, run in the project's folder or below
it, or given a file there: `knave check`, `types`, `lint`, `expand`, `emit`,
`build`, `run`, `test`, `task`, `eval`, `repl`, `doc --write`, `add` and
`remove`. `knave fmt` reports it as a warning and formats the files all the
same.

The project file of a library that the project lists reports it the same way, at
that file.

## Erroneous example

```knave
;; project.knv
(defproject greeter
  (libraries (hints :git "https://example.com/hints.git")))
;; src/main.knv
(use hints hint)

(defn main () (println (hint)))
;; hints/project.knv
(defproject hints)
;; hints/src/lib.knv
(export hint)

(defn hint () "hello")
```

## Fixes

When the library's files are on disk, name their folder with `:path` instead:

```knave
;; project.knv
(defproject greeter (libraries (hints :path "hints")))
;; src/main.knv
(use hints hint)

(defn main () (println (hint)))
;; hints/project.knv
(defproject hints)
;; hints/src/lib.knv
(export hint)

(defn hint () "hello")
```
