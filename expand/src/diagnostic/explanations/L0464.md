A `rust` template bound by a `def` lists clauses, and a call uses the first
clause in written order that matches the type its `where` binder takes. This
error reports a clause when an earlier clause matches every type that it
matches. The earlier clause does so when it names the same type or the same
trait, when it names a trait that the later clause's type implements, or when
the later clause names a trait that requires the earlier clause's trait.

So `(ord ...)` before `(i64 ...)`, before `((box i64) ...)`, or before a program
struct whose `derive` lists `ord` reports it, and so does `(partial-eq ...)`
before a struct whose `partial-eq` the compiler infers. So does
`(partial-ord ...)` before `(ord ...)`, because `ord` requires `partial-ord`.
Each clause is compared with every earlier clause, so the `i64` clause of
`(ord ...) (partial-ord ...) (i64 ...)` reports it. A type before a trait, such
as `(i64 ...)` before `(ord ...)`, and a trait before a trait that it requires,
such as `(ord ...)` before `(partial-ord ...)`, report nothing.

A template with clauses written inline, outside a `def`, reports `L0603` when
the program is built instead.

## Erroneous example

```lisp
(def larger
  (rust "crate::rt::max({0}, {1})"
    (where ((a partial-ord)) (fn (a a) a))
    (ord "std::cmp::max({0}, {1})")
    (i64 "i64::max({0}, {1})")))

(defn main () (println (larger 1 2)))
```

## Fixes

Write the `i64` clause before the `ord` clause:

```lisp
(def larger
  (rust "crate::rt::max({0}, {1})"
    (where ((a partial-ord)) (fn (a a) a))
    (i64 "i64::max({0}, {1})")
    (ord "std::cmp::max({0}, {1})")))

(defn main () (println (larger 1 2)))
```

Or drop the `i64` clause, and let the `ord` clause serve `i64` too:

```lisp
(def larger
  (rust "crate::rt::max({0}, {1})"
    (where ((a partial-ord)) (fn (a a) a))
    (ord "std::cmp::max({0}, {1})")))

(defn main () (println (larger 1 2)))
```
