Each file loads as one module. When a second module path reaches a file that
another module path already loaded, the `use` binds to that module. The
spelling to drop reports this error when it is in the program's own files and
the other spelling is not in code that a command generates, because two
spellings of one module make the program harder to read. A `use` in a library's
files is not reported. Two paths can reach one file through a folder that is a
symbolic link, or through the folder of a library that lies inside the source
root. The help writes the path to keep: the library's path when one of the two
is a library's, and otherwise the path that loaded the file first. One exception
keeps a library apart: when code that a command generates loads a library's
file by a local path and the library loads it by its own path, the two load as
separate modules.

## Erroneous example

```knave
;; project.knv
(defproject tiles
  (libraries (shapes :path "src/vendor/shapes")))
;; src/main.knv
(use shapes area)
(use vendor/shapes/src/lib)

(defn main () (prn (area 2)))
;; src/vendor/shapes/project.knv
(defproject shapes)
;; src/vendor/shapes/src/lib.knv
(export area)

(defn area (side) (* side side))
```

## Fixes

Use the file by its library's module path:

```knave
;; project.knv
(defproject tiles
  (libraries (shapes :path "src/vendor/shapes")))
;; src/main.knv
(use shapes area)

(defn main () (prn (area 2)))
;; src/vendor/shapes/project.knv
(defproject shapes)
;; src/vendor/shapes/src/lib.knv
(export area)

(defn area (side) (* side side))
```
