A project's `libraries` give each library a name, and a module path that starts
with that name, such as `hints` or `hints/extra`, loads from the library. In a
project, `knave test` given a folder or none, `knave task`, `knave check`, which
reads `tasks/`, and `knave doc --write`, which reads the source root, read every
`.knv` file in a folder as a module. A file's module path is its path without
`.knv` from the folder the command reads, except that `knave test` takes it from
the source root when the file lies inside it. This error reports each such file
whose module path starts with the name of a library the project lists, such as
`tests/hints.knv`, `tasks/hints/extra.knv`, `tests/unit/hints.knv` under `knave
test tests/unit`, or `src/hints.knv` under `knave doc --write`. The library
loads in the file's place, so the file's tests or tasks would never run, and its
page would document the library instead.

## Erroneous example

```knave
;; knave test
;; project.knv
(defproject app (libraries (hints :path "libs/hints")))
;; src/main.knv
(defn main () (println "rest"))
;; tests/hints.knv
(deftest adds (assert (= (+ 1 1) 2)))
;; libs/hints/project.knv
(defproject hints)
;; libs/hints/src/lib.knv
(export shout)

(defn shout (text) (str text "!"))
```

## Fixes

Give the file a module path of the program's own, such as `hint-tests`:

```knave
;; knave test
;; project.knv
(defproject app (libraries (hints :path "libs/hints")))
;; src/main.knv
(defn main () (println "rest"))
;; tests/hint-tests.knv
(deftest adds (assert (= (+ 1 1) 2)))
;; libs/hints/project.knv
(defproject hints)
;; libs/hints/src/lib.knv
(export shout)

(defn shout (text) (str text "!"))
```
