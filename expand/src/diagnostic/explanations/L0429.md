A `try` reads the success out of a value whose type is `result` or `option`.
This error reports a `try` whose value has some other type when the compiler
checks the `try`, such as an integer, a string, a vector, a struct, or an enum
that the program defines, even one with an `ok` and an `err` variant.

The compiler checks a function from top to bottom, so the value's type must be
known when the compiler reaches the `try`. A parameter that no signature types
and that the body has not used yet has no type there, and a `try` around it
reports this error. So does a `try` around a call of a function in the current
recursive group, such as the function itself, while that function's result is
still unknown. The compiler reports that case once for each recursive group.

## Erroneous example

```lisp
(defn add-one (value) (some (+ 1 (try value))))

(defn main () (println (unwrap (add-one (some 1)))))
```

## Fixes

State the parameter's type in a signature, so the `try` sees an option:

```lisp
(type add-one (fn ((option i64)) (option i64)))

(defn add-one (value) (some (+ 1 (try value))))

(defn main () (println (unwrap (add-one (some 1)))))
```

Or take a plain number, and leave out the `try`:

```lisp
(defn add-one (value) (+ 1 value))

(defn main () (println (add-one 1)))
```
