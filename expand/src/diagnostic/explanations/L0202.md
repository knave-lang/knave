Macros are hygienic: each expansion adds its own scope to the names it writes,
so a definition that a macro introduces stays apart from a definition of the
same spelling elsewhere. A name refers to the definition of that spelling whose
scopes form the largest subset of the name's own. Here two definitions of one
spelling, each written by a different expansion, tie for the largest, and
neither is closer.

One way this happens is a macro that defines a second macro: a name that the
second macro's expansion writes carries the scopes of both expansions, so a
definition from the first expansion and one from the second tie.

## Erroneous example

```lisp
(use code list)

(defmacro make-definer (name variable)
  (template
    (do (def shared 1)
        (defmacro (unquote name) ()
          (list (quote do)
                (list (quote def) (quote (unquote variable)) 2)
                (quote (def total shared)))))))

(make-definer define-second shared)

(define-second)

(defn main ()
  (println "done"))
```

`make-definer` defines `shared`, and `define-second` defines the `shared` that
the call passes in. The `shared` in `(def total shared)` can refer to both.

## Fixes

Give the second definition another name, so that one `shared` remains:

```lisp
(use code list)

(defmacro make-definer (name variable)
  (template
    (do (def shared 1)
        (defmacro (unquote name) ()
          (list (quote do)
                (list (quote def) (quote (unquote variable)) 2)
                (quote (def total shared)))))))

(make-definer define-second other)

(define-second)

(defn main ()
  (println "done"))
```
