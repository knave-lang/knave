The compiler lowers and checks a macro's definition when the first call runs
the macro. When that fails, such as when the body names something undefined,
runs code that only the program runs, or the `macro` form itself is malformed,
the compiler reports the failure once, where the definition stands, and the
first call adds nothing. This error marks each later call of the same macro,
whether the call stands in a function body or at module level.

A `defmacro` that fails its own checks, such as one whose docstring stands
before its parameters, reports only that failure, and its calls report
nothing.

## Erroneous example

```lisp
(defn main ()
  (println (plus-one 1))
  (println (plus-one 2)))

(defmacro plus-one (value) (+ value 1))
```

## Fixes

Return the addition as code, so that the program runs it:

```lisp
(defn main ()
  (println (plus-one 1))
  (println (plus-one 2)))

(defmacro plus-one (value) (template (+ (unquote value) 1)))
```

When the addition needs no macro, write a function:

```lisp
(defn main ()
  (println (plus-one 1))
  (println (plus-one 2)))

(defn plus-one (value) (+ value 1))
```
