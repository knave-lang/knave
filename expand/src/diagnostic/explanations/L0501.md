A value of a type that is not `Copy`, such as a `vec` or a `string`, has one
owner. Passing it to a function that takes it by value, or storing it in another
value, moves it: the new place owns it, and the old name holds nothing. Reading
the old name after the move is an error, because knave emits Rust and never
copies a value that the source does not copy.

## Erroneous example

```lisp
(defn main ()
  (local grid (vec 1 2))
  (local next (assoc grid 0 3))
  (println (at next 0) " " (at grid 0)))
```

`assoc` takes `grid` by value and returns a changed vector, so `grid` is gone
when the last line reads it.

## Fixes

Read the value before it moves:

```lisp
(defn main ()
  (local grid (vec 1 2))
  (local first (at grid 0))
  (local next (assoc grid 0 3))
  (println (at next 0) " " first))
```

Or `clone` it, when both places need their own copy:

```lisp
(defn main ()
  (local grid (vec 1 2))
  (local next (assoc (clone grid) 0 3))
  (println (at next 0) " " (at grid 0)))
```
