A number literal takes its type from where it is used, or `i64` or `f64` when
nothing fixes it. This error reports a literal whose value that type cannot
hold: an integer below the smallest or above the largest value of its integer
type, such as `300` as a `u8`, `-1` as a `u32`, or `9223372036854775808` with
the default `i64`, or a float too large for its float type, such as `1e39` as an
`f32`. A float too large even for `f64`, such as `1e400`, reports it whatever
its type. An integer literal never reports it as a float type.

The check reads only literals, so arithmetic whose result is too large for its
type does not report it. A literal whose type is a type parameter reports
`L0441` or `L0414` instead, by the traits that the parameter requires, and a
number too large for 128 bits reports `L0107` when the file is read.

## Erroneous example

```lisp
(defn main ()
  (let (level (the u8 300))
    (println level)))
```

## Fixes

Give the value a type that holds it:

```lisp
(defn main ()
  (let (level (the u16 300))
    (println level)))
```

Or keep the type, and write a value that it holds:

```lisp
(defn main ()
  (let (level (the u8 255))
    (println level)))
```
