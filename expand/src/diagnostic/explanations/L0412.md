The `code` module holds builtins that work on forms while macros expand, such as
`first`, `len` and `symbol?`. This error reports a name from the `code` module
in code that the program runs, whether the code calls it or passes it as a
value, as in `(map first items)`.

A definition that uses the `code` module or `quote`, and each definition that
depends on one, is checked as program code only when `main` reaches it. So a
function that calls `first` from `code` reports nothing until `main` calls it,
and a function that a macro uses reports this error once `main` calls it too. A
function that a prelude macro uses, such as `map-list` from `prelude/macros`,
reports it inside the prelude when `main` calls it. Importing `(use code len)`
hides the runtime `len` in that module, so `(len "abc")` there reports this
error. A `quote` in code that `main` reaches reports `L0442` instead.

## Erroneous example

```knave
(use code first)

(defn head-of (items) (first items))

(defn main () (println (head-of (vec 1 2))))
```

## Fixes

Drop the import, and read the vector with a runtime function:

```knave
(defn head-of (items) (at items 0))

(defn main () (println (head-of (vec 1 2))))
```

Or, to work on a form, make `head-of` a macro:

```knave
(use code first)

(defmacro head-of (form) (first form))

(defn main () (println (head-of (1 2))))
```
