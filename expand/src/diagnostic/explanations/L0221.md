A `rust` template can write a type parameter of its signature by name, as
`{target}` does in `"{0}.parse::<{target}>()"`, and each call fills it with the
type that the parameter takes there. A misspelled name, or one that the
signature's `where` does not bind, reports this error, and so does any named
placeholder in a template whose signature has no `where`. The check covers the
template right after `rust` and the template of each clause after the type,
whether the `rust` form is bound by `def` or written inside a function.

## Erroneous example

```lisp
(def parse-as
  (rust "{0}.parse::<{wanted}>().unwrap()"
    (where ((target from-str))
      (fn ((ref str)) target))))

(defn main ()
  (let (year (the i64 (parse-as "2024")))
    (println year)))
```

## Fixes

Spell the placeholder as the `where` spells the variable:

```lisp
(def parse-as
  (rust "{0}.parse::<{target}>().unwrap()"
    (where ((target from-str))
      (fn ((ref str)) target))))

(defn main ()
  (let (year (the i64 (parse-as "2024")))
    (println year)))
```

A signature without a `where` gains one around it, binding the variable that the
placeholder writes:

```lisp
(def size-of
  (rust "std::mem::size_of::<{item}>()"
    (where (item) (fn ((ref item)) usize))))

(defn main ()
  (println (size-of (ref (the u8 3)))))
```
