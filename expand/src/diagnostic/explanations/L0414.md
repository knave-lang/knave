A number literal such as `1` or `1.5` gets its type from where it is used. This
error reports a number literal whose type is a type parameter, such as the
result of `(where (a) (fn (a) a))` or the item pushed into a `(vec a)`, when the
parameter requires no trait.

A parameter whose traits are implemented only by types that hold the literal
accepts it, and one with an implementor that cannot hold it, such as `display`,
`number` with `300`, or a `deftrait` implemented for `string`, reports `L0441`
instead. A string literal reports `L0401`. A use of the parameter that needs a
trait, such as `(= x 1)`, reports `L0440` first.

## Erroneous example

```lisp
(type pick (where (a) (fn (a) a)))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```

## Fixes

Write `(a number)` in the `where`, so that `a` stands only for number types:

```lisp
(type pick (where ((a number)) (fn (a) a)))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```

Or drop the type parameter, and name the type:

```lisp
(type pick (fn (i64) i64))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```
