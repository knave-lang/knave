A docstring example is a form on a line of its own, with the expected result on
the next line after an arrow, `=>`. The test runner reads the examples of the
program's modules: `knave test` does, and so does `knave check` on a program
whose `main` calls `(run-tests)`, or that writes `(check-library-examples)`,
which reads the examples of its libraries. This error reports an example whose
expected result is not exactly one complete form ending its line, such as an
unclosed list, `6 7`, a stray `)`, or an empty result. A `;` comment after the
form is allowed, and a result whose last line ends in `...` is not compared, so
it reports nothing whatever it holds.

`knave check` and `knave build` of a program that calls neither `run-tests` nor
`check-library-examples` do not read examples, so they report nothing.

## Erroneous example

```knave
(defn twice (x)
  "Doubles a number.

  (twice 3)
  => (6"
  (* 2 x))

(defn main () (run-tests))
```

## Fixes

Write the number alone after `=> `:

```knave
(defn twice (x)
  "Doubles a number.

  (twice 3)
  => 6"
  (* 2 x))

(defn main () (run-tests))
```
