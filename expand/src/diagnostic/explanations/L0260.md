Every part of a module path is a name: the path names a file from the root
directory, one name per directory. A `use` whose path holds a part that is not a
name, such as `./shapes`, `geometry/../shapes`, `geometry//shapes` or an
absolute path, reports this error, because the same file would load a second
time as a different module.

The help writes the module path that loads the file the path leads to: the
shortest path from a root directory that reaches the file, so a test that writes
`../src/parser` is told `parser`, and a library's module is told its path from
the library's root directory. A file of another library is told its module path
under the innermost library that holds it, such as `shapes` for the library's
root file. When the module cannot use that library, a note names the library and
the help says to list it in the project file. A path without `..` or a leading
`/` that no root names that way is told itself without its `.` and empty parts,
such as `text/pad` for `./text//pad/`, when that path loads a file. If the file
exists but no module path that the module can use loads it, a note names the
file, and a task's path into `tests`, such as `../tests/support`, is told that a
task cannot reach `tests`. If no file lies at the path, a note says so.

## Erroneous example

```knave
;; project.knv
(defproject tiles)
;; src/main.knv
(use ./shapes area)

(defn main () (prn (area 2)))
;; src/shapes.knv
(export area)

(defn area (side) (* side side))
```

## Fixes

Write the path from the root directory:

```knave
;; project.knv
(defproject tiles)
;; src/main.knv
(use shapes area)

(defn main () (prn (area 2)))
;; src/shapes.knv
(export area)

(defn area (side) (* side side))
```
