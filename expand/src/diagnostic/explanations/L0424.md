A written `derive` lists a struct's or an enum's traits exactly, so each type
takes at most one. This error reports each `derive` after the first that names
the same type, whatever either form lists, even when the first is an empty
`(derive point)` or both list the same traits. The compiler reads only the
first form, so it checks nothing in a later one, not even a trait that no
`derive` accepts.

An enum declared with a `rust` clause takes no `derive` at all, so each
`derive` of it reports `L0435` instead.

## Erroneous example

```knave
(defstruct point
  :x i64
  :y i64)

(derive point clone)

(derive point debug)

(defn main ()
  (println (:x (->point :x 1 :y 2))))
```

## Fixes

List `clone` and `debug` in one form:

```knave
(defstruct point
  :x i64
  :y i64)

(derive point clone debug)

(defn main ()
  (println (:x (->point :x 1 :y 2))))
```
