The REPL keeps each input that defines something, such as a `defn` or a `use`,
and checks the kept inputs again whenever a later definition arrives. This
warning reports an earlier input that the later definition pushes out of that
store, so the names it bound are no longer bound. A later definition pushes one
out when the earlier input no longer checks, such as after a redefinition, or a
change on disk to a module file, that gives a function it calls a new number of
parameters. An input that calls a name pushed out this way is pushed out in
turn. A later definition also pushes out an earlier input when it redefines one
name of that input and the input bound other names too, as `(defn ->point ...)`
does after `(defstruct point ...)`, which also binds `->point`, or when a later
lone `document` of a term follows an earlier input that defines nothing and
documents that term along with others. An earlier input that also defines a
name keeps its docstrings.

When the later definition has an error of its own, the REPL refuses it and keeps
every earlier input, so nothing is pushed out. A redefinition after which every
earlier input still checks pushes out nothing either.

Only `knave repl` reports this warning. The forms of the example below, written
in one file, report `L0203` instead.

## Erroneous example

```lisp
;; knave repl
(defstruct point :x i64)
(defn ->point (x) x)
```

## Fixes

Give the new function a name of its own:

```lisp
;; knave repl
(defstruct point :x i64)
(defn make-point (x) (->point :x x))
(println (:x (make-point 3)))
```
