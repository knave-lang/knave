`fn`, `fn-mut`, `fn-once`, `ref`, `mut`, `where` and `with` build a type out of
other types, and each takes a fixed number of parts. This error reports one
written with the wrong parts: a function type whose parameter types are not in a
list, or that lacks its parameter list or its result; a `ref` or `mut` with no
type, or with an extra part before the type that is not a lifetime such as `'a`;
a `where` that lacks its variables or its type, or whose variables are not in a
list; a `with` that does not hold exactly two types. One of these names alone in
a type position, as `ref` in `(fn (ref) char)`, reports it too. In a
`rust-trait`, an implementor written as a `where` followed by associated values
reports it when the variables are not in a list, or when a value is not a name
followed by a type.

## Erroneous example

```lisp
(type double (fn i64 i64))
(defn double (n) (* n 2))

(defn main ()
  (println (double 21)))
```

## Fixes

The parameter types of a function type go in a list, even when there is one:

```lisp
(type double (fn (i64) i64))
(defn double (n) (* n 2))

(defn main ()
  (println (double 21)))
```
