An `at` place in `set!` writes into a vector by index or into a map by key, and
the two emit different Rust. When the base of the place has the type of a
parameter of a top-level function with no written type, such as the parameter
itself or a local bound to it, and nothing in the body fixes that type, the
parameter takes the collection that its callers pass. This error reports such a
parameter when its callers pass more than one collection type and not all of
them are vectors, such as a vector and a map, two maps with different value
types, or a `sorted-map` and a `hash-map`. A caller that passes its own such
parameter on counts by what its callers pass.

Callers that all pass one type, or only vectors, report nothing, and neither
does a function that nothing calls. A body that also reads the parameter as a
vector, as `(at counts key)` in a value position does, makes it a vector, so a
map argument reports `L0401` instead.

## Erroneous example

```lisp
(defn rename! (models key model)
  (set! (at models key) model))

(defn main ()
  (let (names (hash-map "leaf" "Nissan Leaf")
        years (vec 2011))
    (rename! (mut names) "leaf" "Nissan Leaf Plus")
    (rename! (mut years) 0 2024)
    (println (at years 0))))
```

## Fixes

Keep the function for the map, and change the vector where it lives:

```lisp
(defn rename! (models key model)
  (set! (at models key) model))

(defn main ()
  (let (names (hash-map "leaf" "Nissan Leaf")
        years (vec 2011))
    (rename! (mut names) "leaf" "Nissan Leaf Plus")
    (set! (at years 0) 2024)
    (println (at years 0))))
```
