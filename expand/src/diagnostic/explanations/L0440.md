A `type` signature's `where` gives each type parameter its traits, such as `(a
partial-ord)`. This error reports a use in the function's body, at any depth,
including inside a `fn`, that needs a trait of a type parameter that the
parameter lacks, such as `<` on an `(a)`, `=` on an `(a display)`, a `clone`, a
call to a function whose own `where` needs the trait, or a method of a
`deftrait`.

A parameter has a trait when its `where` lists the trait or a trait that
requires it, so `(a ord)` covers `<`. It also has a trait with no second type
when every type that its listed traits allow implements that trait, so `(a
number)` covers `<`. A function without a `type` signature gets its traits
inferred, and so does a type parameter of an `impl`'s implementor, such as `a`
in `(vec a)`, so neither reports this error. A signature that applies an
associated type of the trait to the parameter, such as `(output a)`, reports
`L0453` instead.

## Erroneous example

```knave
(type smaller (where (a) (fn (a a) a)))

(defn smaller (x y) (if (< x y) x y))

(defn main () (println (smaller 3 4)))
```

## Fixes

Bound `a` by `partial-ord`, the trait of `<`:

```knave
(type smaller
  (where ((a partial-ord)) (fn (a a) a)))

(defn smaller (x y) (if (< x y) x y))

(defn main () (println (smaller 3 4)))
```

Or drop the signature, so that the compiler infers the trait:

```knave
(defn smaller (x y) (if (< x y) x y))

(defn main () (println (smaller 3 4)))
```
