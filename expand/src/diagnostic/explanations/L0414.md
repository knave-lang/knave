A number literal such as `1` or `1.5` gets its type from where it is used. This
error reports a number literal whose type is a type parameter, such as the
result of `(where (a) (fn (a) a))` or the item pushed into a `(vec a)`, when the
parameter requires no trait declared with `rust-trait`, such as `number` or
`display`.

A parameter that requires only a trait that the program defines with
`deftrait` accepts the literal. A parameter that requires a Rust trait whose
types do not all hold the literal, such as `display`, or `number` with `300`,
reports `L0441` instead. A string literal reports `L0401`. A use of the
parameter that needs a trait, such as `(= x 1)`, reports `L0440` first.

## Erroneous example

```lisp
(type pick (where (a) (fn (a) a)))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```

## Fixes

Write `(a number)` in the `where`, so that `a` stands only for number types:

```lisp
(type pick (where ((a number)) (fn (a) a)))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```

Or drop the type parameter, and name the type:

```lisp
(type pick (fn (i64) i64))

(defn pick (x) 1)

(defn main () (println (pick 2)))
```
