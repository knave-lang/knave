A Rust trait, declared with `rust-trait` or with a `deftrait` that has a `rust`
clause, lists the types that implement it, and Rust needs an impl of the trait
for each one. This error reports a struct of the program in the trait's list
whose derived traits, the ones its emitted `#[derive]` names, do not include the
trait. The compiler compares the last segment of the trait's Rust path, such as
`Debug` in `core::fmt::Debug`, with the struct's derived traits.

The derived traits are the ones the compiler infers, such as `clone` when every
field is `clone`, or the ones that a written `derive` lists or brings. So,
without a written `derive`, a trait whose path ends in `Clone` accepts a struct
whose fields are all `clone`, a trait whose path ends in `Debug` needs `(derive
point debug)`, because the compiler never infers `debug`, and a trait whose path
ends in `Copy` refuses a struct that the program changes in place.

The check covers a struct named alone, inside a `where`, as in `(where ((a hex))
(holder a))`, and as the first type of `with`, as in `(with point i64)`. It does
not cover an enum of the program or a struct inside another type, such as `(ref
point)`.

## Erroneous example

```knave
(defstruct point :x i64 :y i64)

(deftrait hex (rust "std::fmt::LowerHex")
  i64 u8 point)

(type keep (where ((a hex)) (fn (a) a)))
(defn keep (value) value)

(defn main ()
  (println (keep 255)))
```

## Fixes

Name only the number types in the trait:

```knave
(defstruct point :x i64 :y i64)

(deftrait hex (rust "std::fmt::LowerHex")
  i64 u8)

(type keep (where ((a hex)) (fn (a) a)))
(defn keep (value) value)

(defn main ()
  (println (keep 255)))
```
