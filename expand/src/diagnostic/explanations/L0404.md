Some operations work only on a value whose type implements a particular trait,
such as `number` for `+`, `display` for `println`, `partial-eq` for `=`,
`partial-ord` for `<`, `ord` for a `sorted-map` key, `hash` and `eq` for a
`hash-map` key, a trait for each of its methods, and the trait of a function's
`where` bound, or of a bound that inference finds in its body, for the argument.
This error reports a value whose type is fully known and has no implementation
of the trait that the operation requires.

A type built from other types may implement a trait only when its parts do, so
`(= (vec main) (vec main))` reports this error for the function type inside the
vector, and `=` on a struct with a function field reports it for the struct. A
`(box circle)` is its own type, so a method of a trait that `circle` implements
reports this error on the box, while a `(box value)` written where a `(box
shape)` is expected reports it when the value's type has no `shape`
implementation. A `get` on a map reports it when the key type cannot be borrowed
as the type of the lookup value, such as a `usize` looked up in a map with
`string` keys.

A type parameter of a written signature that lacks the trait reports `L0440`
instead, and a type that is still open when checking ends reports `L0407`.

## Erroneous example

```knave
(defn main ()
  (let (prices (sorted-map 2.5 "tea" 1.5 "bun"))
    (println (len prices))))
```

## Fixes

Key the map by a type that has an order, such as whole cents:

```knave
(defn main ()
  (let (prices (sorted-map 250 "tea" 150 "bun"))
    (println (len prices))))
```

Or key it by the name, and store the price as the value:

```knave
(defn main ()
  (let (prices (sorted-map "tea" 2.5 "bun" 1.5))
    (println (len prices))))
```
