Writing `_` for a parameter of a `fn` or `defn`, or for a `let` binding, says
that the body ignores that value. A read of `_` where such a binding is in
scope is this error.

A `_` pattern in a `match` arm binds nothing at all, so reading `_` in that
arm, or anywhere no binding of `_` is in scope, reports `L0201` instead.

## Erroneous example

```lisp
(defn pick-second (_ right) _)

(defn main ()
  (println (pick-second 1 2)))
```

## Fixes

Return the parameter that the body means:

```lisp
(defn pick-second (_ right) right)

(defn main ()
  (println (pick-second 1 2)))
```

When the body needs the first argument, bind it as `left`:

```lisp
(defn pick-first (left _) left)

(defn main ()
  (println (pick-first 1 2)))
```
