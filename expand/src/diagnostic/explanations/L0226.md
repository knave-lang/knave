The Rust text of a type comes from its template, filled with the type's
arguments, so a parameter in the head that no numbered placeholder writes has
no place in that text. The template after the name in a `deftype` or a
`rust-type` must write `{N}` for the parameter at each position `N`, and so
must the type template in a `defenum`'s `(rust "...")` clause. This error
points at the first parameter that the template leaves out.

## Erroneous example

```lisp
(deftype (table key value)
  (rust "std::collections::HashMap<{0}, i64>"))

(def empty-table
  (rust "std::collections::HashMap::new()"
    (where (k v) (fn () (table k v)))))

(def size-of
  (rust "{0}.len()"
    (where (k v) (fn ((ref (table k v))) usize))))

(defn main ()
  (local names (the (table string i64) (empty-table)))
  (println (size-of (ref names))))
```

## Fixes

Write the value type into the template:

```lisp
(deftype (table key value)
  (rust "std::collections::HashMap<{0}, {1}>"))

(def empty-table
  (rust "std::collections::HashMap::new()"
    (where (k v) (fn () (table k v)))))

(def size-of
  (rust "{0}.len()"
    (where (k v) (fn ((ref (table k v))) usize))))

(defn main ()
  (local names (the (table string i64) (empty-table)))
  (println (size-of (ref names))))
```

When every value is an `i64`, the table needs only the key:

```lisp
(deftype (table key)
  (rust "std::collections::HashMap<{0}, i64>"))

(def empty-table
  (rust "std::collections::HashMap::new()"
    (where (k) (fn () (table k)))))

(def size-of
  (rust "{0}.len()"
    (where (k) (fn ((ref (table k))) usize))))

(defn main ()
  (local names (the (table string) (empty-table)))
  (println (size-of (ref names))))
```
