A trait declares an associated type with `(type item)`, and each `impl` of the
trait states it with `(type item value)`. This error reports an `impl` that
omits an associated type the trait declares, that names one the trait lacks,
or that states one twice.

A trait bound to a Rust trait takes no `(type ...)` entry in an `impl`, even
when it has an `associated` clause, so such an entry reports this error too.
An entry with no value, such as `(type item)`, reports `L0210` instead.

## Erroneous example

```lisp
(deftrait container
  (type item)
  (first-item (fn ((ref self)) (option (ref item)))))

(impl container (vec a)
  (first-item (items) (get items 0)))

(defn main ()
  (println (unwrap-or (first-item (ref (vec 4 5))) (ref 0))))
```

## Fixes

State the associated type in the `impl`:

```lisp
(deftrait container
  (type item)
  (first-item (fn ((ref self)) (option (ref item)))))

(impl container (vec a)
  (type item a)
  (first-item (items) (get items 0)))

(defn main ()
  (println (unwrap-or (first-item (ref (vec 4 5))) (ref 0))))
```
