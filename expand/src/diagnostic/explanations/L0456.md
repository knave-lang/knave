A call of a trait method runs the code of one implementor, and the compiler
finds that implementor through the positions of the method's type that hold
`self`. This error reports a use of a method of a program's own `trait` whose
type has no `self` in it, at a call or a place that passes or binds the method
as a value. It reports the first such use in each definition of the program, in
a function that `main` never reaches and in a default method of the same trait
alike, however many implementors the trait has. A trait that declares such a
method and never uses it reports nothing.

`self` inside another type counts, so a method of type `(fn () (vec self))`
takes its implementor from the type that its result must have. An associated
type of the trait does not count: a method of type `(fn (item) i64)`, where
`item` is the trait's `(type item)`, reports this error.

## Erroneous example

```lisp
(defstruct garage :spots i64)

(trait parking (park (fn (i64) i64)))

(impl parking garage
  (park (spot) (+ spot 100)))

(defn main () (println (park 3)))
```

## Fixes

Let `park` take the garage it works on:

```lisp
(defstruct garage :spots i64)

(trait parking (park (fn ((ref self) i64) i64)))

(impl parking garage
  (park (lot spot) (+ spot (:spots lot))))

(defn main () (println (park (->garage :spots 100) 3)))
```

Or make `park` a function of its own:

```lisp
(defn park (spot) (+ spot 100))

(defn main () (println (park 3)))
```
