A macro runs as the head of a call. When a program writes a macro's name alone
as a value, such as an argument of a function, a value in `let` or the result of
a function, the expander calls the macro with the bare name as its form and uses
the code it returns in place of the name. This error reports a macro name in
such a place whose macro fails on the bare name or returns something other than
code. A macro that stops at a limit on the bare name, such as the limit on macro
steps, reports that limit's error instead, such as `L0363`. A macro that takes
its input apart by its parameters, such as one that `defmacro` or `defrule`
defines, fails on a bare name, and so do prelude macros such as `and` and
`println`. Some prelude macros, such as `+`, handle the bare name, so `(reduce
(iter items) 0 +)` works.

A kernel form's name used as a value, such as `if`, reports `L0211` instead.

## Erroneous example

```knave
(defmacro twice (value)
  (template (* 2 (unquote value))))

(defn apply-to-three (function)
  (function 3))

(defn main ()
  (println (apply-to-three twice)))
```

## Fixes

Pass a function that calls the macro:

```knave
(defmacro twice (value)
  (template (* 2 (unquote value))))

(defn apply-to-three (function)
  (function 3))

(defn main ()
  (println (apply-to-three (fn (value) (twice value)))))
```

Define `twice` as a function:

```knave
(defn twice (value)
  (* 2 value))

(defn apply-to-three (function)
  (function 3))

(defn main ()
  (println (apply-to-three twice)))
```
