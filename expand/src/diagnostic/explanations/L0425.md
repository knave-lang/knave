A trait bound may give its trait an extra type, as in `(a (partial-eq b))`,
which is Rust's `A: PartialEq<B>`. Only some traits accept one: a Rust trait
that lists an implementor written as `(with type type)`, such as `partial-eq`,
and a trait of the program that declares an associated type with a
`(type name)` entry. This error reports a bound that gives an extra type to any
other trait, such as `clone`, `eq`, `from-str`, or a program trait that
declares only methods.

The check covers every bound: in the `where` of a `type` signature, of a `rust`
form's type or of a `rust-trait` entry, and in a `rust-trait`'s `requires`
clause. A parameter of `defn` written as `(x (clone i64))` is not a bound, and
reports `L0212` instead.

## Erroneous example

```knave
(type same?
  (where ((a (eq i64))) (fn (a i64) bool)))

(defn same? (x y) (= x y))

(defn main () (println (same? 3 3)))
```

## Fixes

Compare across the two types with `partial-eq`, which takes the extra type:

```knave
(type same?
  (where ((a (partial-eq i64)))
    (fn (a i64) bool)))

(defn same? (x y) (= x y))

(defn main () (println (same? 3 3)))
```

Or give both parameters the one type, and bound it with `eq` alone:

```knave
(type same?
  (where ((a eq)) (fn (a a) bool)))

(defn same? (x y) (= x y))

(defn main () (println (same? 3 3)))
```
