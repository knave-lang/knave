A `derive` form lists a type's traits exactly and turns inference off for that
type. This warning reports a form that changes nothing: removed, the type
still has every trait the form gave it, every function keeps its signature,
and the emitted Rust differs only in its `#[derive]` lines. Inference may add
`eq`, `hash` or `show` once the form goes, and that does not count as a
change. A form on a type of a module other than the entry module must also
change nothing when that module is checked alone, whenever the type is `copy`
with the form or without it. In a project, `knave lint` tries every program
it lints, the test and task programs included, and a form that any of them
needs stays silent. While any program fails to load or check, it tries no
form.

A project that lints its own code never sees the projects that depend on it,
and an exported function or macro can hand a dependent any of the library's
types. So in a project with a `:lib`, every form stays silent whenever its
type is `copy` with the form or without it, because a dependent could change
the type in place. `knave lint` does not expand docstring examples either. A
module's examples run in a linted program only when the test program holds
the module, so a program that holds a module with an example and no test
program holds that module, as a lone file, a project without `tests/` or a
module that `tests/` does not reach, keeps every form whose type is `copy`
with the form or without it.

With `needless-type` on, `knave lint` tries each form in the program without
the `type` declarations that `needless-type` reports, so following both
warnings changes nothing.

A form that inference needs stays silent: one that lists a trait inference
never gives, such as `debug`, `partial-ord`, `ord` or `default`, one that
lists `copy` for a type the program changes in place, and one whose removal
would add `copy` and so change a signature or the template a call picks. A
form that a macro wrote stays silent, and so does every form inside a
docstring example. A form with one trait inference never gives has no
shorter equivalent, because a written form turns inference off, so the
lint never reports part of a form.

Only `knave lint` checks for it, at the cost of one more check of the
program when the project writes a form it may remove: `knave check`,
`knave build` and `knave run` never do.

## Described example

The explanation tests check programs without running the lint rules, so they
run none here. In this program, inference gives `badge` every trait its
form lists, so `knave lint` reports the form:

```text
(defstruct badge
  :name string
  :level int)

(derive badge clone partial-eq)

(defn main ()
  (println (= (->badge :name (str "ana") :level 2)
              (->badge :name (str "ana") :level 2))))
```

## Fixes

Remove the form:

```knave
(defstruct badge
  :name string
  :level int)

(defn main ()
  (println (= (->badge :name (str "ana") :level 2)
              (->badge :name (str "ana") :level 2))))
```

Or keep a form that lists a trait inference never gives, such as `debug` for
interop with Rust code:

```knave
(defstruct badge
  :name string
  :level int)

(derive badge clone partial-eq debug)

(defn main ()
  (println (= (->badge :name (str "ana") :level 2)
              (->badge :name (str "ana") :level 2))))
```
