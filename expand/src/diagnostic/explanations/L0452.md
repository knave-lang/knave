A Rust trait bound by `deftrait` or `rust-trait` lists its implementors, and an
entry written as a `where` ends with one `(name type)` clause for each
associated type that the trait declares with `associated`. This error reports a
clause whose name is a type but not one of the associated types of this trait,
such as `parse-error`, which belongs to `from-str`, or a plain type such as
`string`. The compiler checks a trait's entries in order, whether or not the
program uses the trait, and stops at the first entry that fails.

An entry that has such a clause and also leaves out a declared associated type
reports this error alone. An entry that only leaves one out reports `L0450`
instead, a clause whose name is no type at all reports `L0201`, and an `impl` of
a program's own `trait` that gives a `(type name value)` the trait does not list
reports `L0447`.

## Erroneous example

```lisp
(deftrait addable
  (rust "std::ops::Add")
  (associated (output left) "Output")
  (where () (with i64 i64) (parse-error i64)))

(def add-values
  (rust "{0} + {1}"
    (where ((a (addable b)) b)
      (fn (a b) (output a)))))

(defn main () (println (add-values 2 3)))
```

## Fixes

Name the associated type that `addable` lists:

```lisp
(deftrait addable
  (rust "std::ops::Add")
  (associated (output left) "Output")
  (where () (with i64 i64) (output i64)))

(def add-values
  (rust "{0} + {1}"
    (where ((a (addable b)) b)
      (fn (a b) (output a)))))

(defn main () (println (add-values 2 3)))
```
