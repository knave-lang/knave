When the project and the libraries it lists ask for one crate more than once,
the compiler combines requests that are the same, or versions such as `"1.0"`
and `"1.2"`, which become `"1.2"`. This error reports two requests that it
cannot combine, such as `"1.0"` and `"2.0"`, `"0.1"` and `"0.2"`, `"1.0"` and
`"~1.0"`, or a version and a `:path`. It compares the program's `dependencies`,
the `dependencies` of each library, and then the program's `dev-dependencies`
against them. The `dev-dependencies` of a library do not take part.

The commands that read the project report it as they follow its libraries, and
libraries' own libraries, and stop at the first such problem: `knave check`,
`types`, `lint`, `expand`, `emit`, `build`, `run`, `test`, `task`, `eval`,
`repl`, `doc --write`, `add` and `remove`. `knave fmt` reports it as a warning
and formats the files all the same.

## Erroneous example

```knave
;; project.knv
(defproject greeter
  (dependencies (serde "1.0"))
  (dev-dependencies (serde "2.0")))
;; src/main.knv
(defn main ()
  (println "hello"))
```

## Fixes

With `"1.2"` under `dev-dependencies`, which combines with `"1.0"`,
`knave check` reads the project, and `knave build` fetches the crate from the
registry when it builds the program:

```knave
;; knave check
;; project.knv
(defproject greeter
  (dependencies (serde "1.0"))
  (dev-dependencies (serde "1.2")))
;; src/main.knv
(defn main ()
  (println "hello"))
```
