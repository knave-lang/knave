A trait has two impls for types that can be the same type. Two written impls
report it when their implementors unify, such as two `(display point ...)`
forms, or `(display (tree i64) ...)` beside `(display (tree a) ...)`. A written
impl is any form that writes one, such as `display`, `show` or `impl`, for a
trait of the prelude or of the program. Impls for different instances, such as
`(wrap i64)` and `(wrap bool)`, do not unify and report nothing.

A `derive` that lists a trait, such as `(derive money show)`, beside a written
impl of that trait for any instance of the type reports it too, in either order.
Without the `derive`, a written impl of a `structural` trait such as `show`
replaces the impl that the compiler infers, and reports nothing.

A call that needs the inferred impl of a `structural` trait, such as `prn`
needing `show`, reports it when the program also writes an impl for that type of
another trait that binds the same Rust path.

A written impl of a trait bound to Rust, such as `display`, for a type that is
neither a struct nor an enum, such as `i64`, reports `L0445` instead.

## Erroneous example

```lisp
(defstruct point :x i64 :y i64)

(display point (p) "(" (:x p) ", " (:y p) ")")

(display point (p) (:x p) " " (:y p))

(defn main () (println (->point :x 1 :y 2)))
```

## Fixes

Print the point with the first text only:

```lisp
(defstruct point :x i64 :y i64)

(display point (p) "(" (:x p) ", " (:y p) ")")

(defn main () (println (->point :x 1 :y 2)))
```

Or build the other text in a function:

```lisp
(defstruct point :x i64 :y i64)

(display point (p) "(" (:x p) ", " (:y p) ")")

(defn spaced (p) (str (:x p) " " (:y p)))

(defn main ()
  (let (p (->point :x 1 :y 2))
    (println p)
    (println (spaced p))))
```
