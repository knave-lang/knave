A Rust template writes `{index 1}` where Rust needs an index or a size and the
form takes an `int`. A negative value has no position, so a negative integer
literal passed there, one that ends a branch of an `if` or a `match` or a
block passed there, or one bound to the name a block returns when the block
holds nothing but `let` bindings of literals and names, as in
`(let (x -1 y 0) x)`, is an error before the program runs. A negative value that
only the run computes panics instead, with the message `attempt to use a
negative value as an index or a size`. A position written `{index? 1}` takes a
negative literal, because there a negative index finds no item.

## Erroneous example

```knave
(def item-at
  (rust "&{0}[{index 1}]"
    (where (a)
      (fn ((ref (slice a)) int) (ref a)))))

(defn main ()
  (let (years (vec 2019 2023))
    (println (deref (item-at years -1)))))
```

## Fixes

Count the position from the front, starting at 0:

```knave
(def item-at
  (rust "&{0}[{index 1}]"
    (where (a)
      (fn ((ref (slice a)) int) (ref a)))))

(defn main ()
  (let (years (vec 2019 2023))
    (println (deref (item-at years 1)))))
```
