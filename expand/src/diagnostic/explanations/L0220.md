`(try value)` unwraps a `result` or an `option`, and on an `err` or a `none`
returns it from the nearest enclosing function, as Rust's `?` does. This error
reports a `try` in the value of a module-level `def` that no function encloses,
wherever it sits in that value, including the `try` that `let-try` or `try->`
writes. A `try` inside a `fn` in that value is allowed.

## Erroneous example

```lisp
(def port (try (parse "8080")))

(defn main ()
  (println port))
```

## Fixes

With a function that returns a `result`:

```lisp
(defn port ()
  (ok (+ (try (parse "8080")) 1)))

(defn main ()
  (match (port)
    ((ok value) (println value))
    ((err problem) (println problem))))
```
