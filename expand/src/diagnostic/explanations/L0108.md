The reader counts the lists that are open around each `(`, and this error
reports a `(` read while 1,024 lists are already open, so the list it opens
would sit 1,025 deep. Every later stage of the compiler walks a form by
recursion, and the limit keeps that walk inside its stack.

Every command that reads source reports it, `knave fmt` included, and so does a
command that reads a project file nested that deep. Code inside a docstring is
part of a string, so `knave fmt` reports `L0109` for it instead. A macro whose
output nests past the same depth reports `L0325`.

## Described example

No example of a size to show reaches the limit, so the explanation tests run
none here. A file whose `main` prints a value inside 1,023 nested `vec` calls,
with the middle left out, opens its last `(` inside `defn`, `println` and 1,022
`vec` lists:

```text
(defn main () (println (vec (vec (vec … 1,023 calls in all … 1)))))
```

## Fixes

Split the deep form: move an inner part into a function of its own, and call
the function in the outer form, so that no single form nests that deep. A
generator that writes such a file can split its output the same way.
