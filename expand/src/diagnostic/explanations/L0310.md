Macro code reads the value of each name it uses while it runs. A built-in of
macro code and a definition made by `def` or `defn` have such a value, and this
error reports a name of any other kind.

## Described example

No program reaches this error, so the explanation tests run no example here.
The expander turns away every other kind of name before macro code runs, such
as a macro's name used as a value, which reports `L0304`, a case with no
fields, which reports `L0316`, a case with fields, which reports `L0233`, a
kernel form's name, such as `if`, which reports `L0211`, a definition that only
the program can run, which reports `L0306`, and the name of a type, which is no
value and reports `L0201`. The error stays as a guard in the interpreter, in
case a new kind of name gets past those checks.

## Fixes

In macro code, read only built-ins of macro code and definitions.
