A trait method whose first parameter is `self` receives the implementor itself,
not a reference to it, and Rust passes a value only when it knows the value's
size at compile time. This error reports an `impl` of a trait that the program
defines when the implementor is `str` or a slice, such as `(slice i64)` or
`(slice a)`. It reports once for each method that the `impl` writes whose first
parameter in the trait is `self`.

A method whose first parameter is `(ref self)` or `(mut self)` passes a
reference, so the same `impl` is fine. The check reads only the methods that the
`impl` writes: a method with a default body that the `impl` leaves out reports
nothing.

A trait that `rust-trait` binds, such as `display`, reports `L0445` for such an
implementor instead, and an implementor written as `(ref str)` reports `L0210`.

## Erroneous example

```lisp
(deftrait measured (size (fn (self) usize)))

(impl measured str (size (text) (len text)))

(defn main () (println (size "abc")))
```

## Fixes

Declare the method's first parameter as `(ref self)`:

```lisp
(deftrait measured (size (fn ((ref self)) usize)))

(impl measured str (size (text) (len text)))

(defn main () (println (size "abc")))
```

Or implement the trait for `string`, the owned text type:

```lisp
(deftrait measured (size (fn (self) usize)))

(impl measured string (size (text) (len text)))

(defn main () (println (size (str "abc"))))
```
