A `use` loads the module it names, and a module stays loading until the compiler
has expanded all of its forms. This error reports a `use` that names a module
still loading, which is a module that imports, directly or through other
modules, the module that holds the `use`. Two modules that import each other
report it, and so does a module that imports itself. The entry file is a module
too, named by its path from the source root without `.knv`, such as `main` for
`src/main.knv`, so a module that the entry reaches and that imports the entry
reports it as well. `knave test` and `knave repl` report it the same way, with
the tests or the prompt in the place of the entry.

A module that several others import, with no `use` that leads back to them,
loads once and reports nothing.

## Erroneous example

```lisp
;; project.knv
(defproject shop)
;; src/main.knv
(use money price)

(defn main ()
  (println (price 3)))
;; src/money.knv
(use tax rate)

(export base price)

(def base 100)

(defn price (count) (* count base (rate)))
;; src/tax.knv
(use money base)

(export rate)

(defn rate () (if (> base 50) 2 1))
```

## Fixes

Let `tax` take the value it reads as an argument, so it imports nothing:

```lisp
;; project.knv
(defproject shop)
;; src/main.knv
(use money price)

(defn main ()
  (println (price 3)))
;; src/money.knv
(use tax rate)

(export base price)

(def base 100)

(defn price (count) (* count base (rate base)))
;; src/tax.knv
(export rate)

(defn rate (amount) (if (> amount 50) 2 1))
```

Or define `rate` in `money` itself:

```lisp
;; project.knv
(defproject shop)
;; src/main.knv
(use money price)

(defn main ()
  (println (price 3)))
;; src/money.knv
(export base price)

(def base 100)

(defn rate () (if (> base 50) 2 1))

(defn price (count) (* count base (rate)))
```
