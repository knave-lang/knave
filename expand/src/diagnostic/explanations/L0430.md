A variant pattern without its enum's name, such as `on` or `(dim level)`, names
a variant of whichever enum the matched value has. When the compiler reaches a
`match` and does not know the matched value's type yet, it collects, for each
arm, the enums that have the arm's variant name, and keeps the enums common to
every such arm. This error reports that two or more enums are left. An arm whose
name fits one enum only, or a name written with its enum, as in `light/on`,
leaves one enum and settles the type. The enums include the prelude's, so a
program enum with a `some` variant overlaps `option`.

A nested pattern reports this error too, when the type of the part it matches
is still unknown, such as the payload of a generic enum, and two or more enums
have its name. When the matched value's type is known, such as from a `type`
signature, the compiler reads each name in that type's enum.

## Erroneous example

```lisp
(defenum light on off)

(defenum switch on off)

(defn describe (value) (match value (on "lit") (off "dark")))

(defn main () (println (describe light/on)))
```

## Fixes

Write `light/on` in the first arm:

```lisp
(defenum light on off)

(defenum switch on off)

(defn describe (value) (match value (light/on "lit") (off "dark")))

(defn main () (println (describe light/on)))
```

Or state the parameter's type in a signature:

```lisp
(defenum light on off)

(defenum switch on off)

(type describe (fn (light) (ref str)))

(defn describe (value) (match value (on "lit") (off "dark")))

(defn main () (println (describe light/on)))
```
