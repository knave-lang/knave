In the template of a `deftype` or a `rust-type`, `{0}` stands for the first
parameter in the head and `{1}` for the second. A name between braces, such as
`{item}`, or a binder such as `{!item}` is this error, even when the name
matches a parameter in the head. The rule holds for the template after the name,
for the template of each clause, and for the `(rust "...")` clause of a
`defenum` once that clause holds a numbered placeholder.

## Erroneous example

```lisp
(deftype (boxed item) (rust "Box<{item}>"))

(def box-new
  (rust "Box::new({0})" (where (a) (fn (a) (boxed a)))))

(def unbox
  (rust "*{0}" (where (a) (fn ((boxed a)) a))))

(defn main ()
  (local seven (box-new 7))
  (println (unbox seven)))
```

## Fixes

`item` is the first parameter in the head of `boxed`, so its position is `0`:

```lisp
(deftype (boxed item) (rust "Box<{0}>"))

(def box-new
  (rust "Box::new({0})" (where (a) (fn (a) (boxed a)))))

(def unbox
  (rust "*{0}" (where (a) (fn ((boxed a)) a))))

(defn main ()
  (local seven (box-new 7))
  (println (unbox seven)))
```
