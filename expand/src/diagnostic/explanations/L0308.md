Macro code runs at compile time, so the compiler lowers each module-level
definition that a macro body names, and each definition that those name in turn.
This error marks a name in that code whose definition already failed, such as a
`def` whose value names something undefined, a `defn` whose docstring stands
before its parameters, or a function whose body reaches code that only the
program runs. The definition's own error is reported where the definition
stands. The compiler checks every macro, so a macro that no call runs reports
this error too.

A function whose body reaches code that only the program runs reports that
code's own error for the first macro that the compiler checks through it, such
as `L0306` for a program function or `L0317` for a `match`, and this code for
each later one. A name in program code whose definition failed reports nothing
more than the definition's own error.

## Erroneous example

```lisp
(use code number-add)

(defmacro answer () (doubled 21))

(defn doubled "Doubles a count."
  (count)
  (number-add count count))

(defn main ()
  (println (answer)))
```

## Fixes

Write the docstring after the parameter list:

```lisp
(use code number-add)

(defmacro answer () (doubled 21))

(defn doubled (count)
  "Doubles a count."
  (number-add count count))

(defn main ()
  (println (answer)))
```
