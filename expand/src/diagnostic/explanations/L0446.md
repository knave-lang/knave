A trait may name other traits that each of its implementors must also
implement. `deftrait` lists them after the trait's name, as in
`(deftrait (shape (display)) ...)`, and a trait bound to Rust lists them in a
`(requires ...)` clause. This error reports an `impl` whose implementor lacks
one of those traits, once for each trait it lacks.

The compiler counts a written `impl`, an implementor that the trait lists,
such as `i64` for `display`, and a trait that a struct gets from its fields
when no `derive` names its traits, such as `clone`. A written `derive` lists
the type's traits exactly, so a struct whose `derive` leaves out `clone`
reports this error under a trait that names `clone`.

## Erroneous example

```lisp
(deftrait (shape (display))
  (area (fn ((ref self)) f64)))

(defstruct circle :radius f64)

(impl shape circle (area (c) (:radius c)))

(defn main () (println (area (->circle :radius 1.0))))
```

## Fixes

Write a `display` for the struct:

```lisp
(deftrait (shape (display))
  (area (fn ((ref self)) f64)))

(defstruct circle :radius f64)

(display circle (c) "circle")

(impl shape circle (area (c) (:radius c)))

(defn main () (println (area (->circle :radius 1.0))))
```

Or remove `display` from the trait's head:

```lisp
(deftrait shape
  (area (fn ((ref self)) f64)))

(defstruct circle :radius f64)

(impl shape circle (area (c) (:radius c)))

(defn main () (println (area (->circle :radius 1.0))))
```
