A module path names a file from the root directory, one name per directory. A
`use` whose path holds a `.` or `..` part, such as `./shapes` or
`geometry/../shapes`, reports this error, because the same file would load a
second time as a different module.

The help writes the module path of the file that the path leads to, from the
root directory that reaches it, so a test that writes `../src/parser` is told
`parser`. Inside a library, the help writes the path from the library's root
directory. If the file exists but no module path that the module can use names
it, as a task's `../tests/support`, a note names the file. If no file lies at
the path, the help writes the path without its `.` and `..` parts, or, when the
path leaves the root directory or names it, a note says that the path names no
file under it.

## Erroneous example

```knave
(use ./shapes area)

(defn main () (prn (area 2)))
```

## Fixes

Write the path from the root directory:

```knave
(use shapes area)

(defn main () (prn (area 2)))
```
