A `has` bound, `(has :field type)`, lets a function read a field of any struct
that declares it with that read type. The function then reads the field through
a getter of a Rust trait, so this error reports a function that does more with
the field, or with the value that holds it, than that getter allows: it changes
the field, moves a value that is not Copy, lets a borrow of the field leave the
function, reads a field that holds a function, or, once a call reaches it,
names the read with a type variable. It also reports a struct with an open type argument that reaches the
bound, structs that reach it and read the field as different types, two `has`
bounds that read one field as different types, and a trait or getter name that
the program already uses. Naming the struct in the signature lifts each limit
when one struct reaches the function. When two or more reach it, write one
function for each struct.

## Erroneous example

```knave
(defstruct counter
  :count int)

(defstruct timer
  :count int)

(type bump!
  (where ((a (has :count int)))
    (fn ((mut a)) unit)))

(defn bump! (x)
  (set! (:count x) (+ (:count x) 1)))

(defn main ()
  (local c (->counter 1))
  (bump! (mut c))
  (println (:count c)))
```

## Fixes

Name the struct in the signature:

```knave
(defstruct counter
  :count int)

(type bump! (fn ((mut counter)) unit))

(defn bump! (x)
  (set! (:count x) (+ (:count x) 1)))

(defn main ()
  (local c (->counter 1))
  (bump! (mut c))
  (println (:count c)))
```
