In a `match` arm, a bare name spelled as a variant with no payload of the
matched enum, such as `high` for an enum `level`, is a pattern that matches
that variant. It binds nothing. This holds for a bare name nested in a variant
pattern, such as `(some high)`, and for the patterns of `let-match`.

This error reports the same name used as a value in that arm's body, at any
depth, including inside a `fn`, when no binding of the name exists outside the
`match`. When one does, such as a parameter or a `def` of that name, the name
in the body is that binding, and nothing is reported. In another arm, the name
is unbound, `L0201`.

## Erroneous example

```lisp
(defenum level
  low
  high)

(defn raise (l)
  (match l (low level/high) (high high)))

(defn main ()
  (match (raise level/low)
    (low (println "low"))
    (high (println "high"))))
```

## Fixes

Use the qualified constructor `level/high` in the body, as the first arm does:

```lisp
(defenum level
  low
  high)

(defn raise (l)
  (match l (low level/high) (high level/high)))

(defn main ()
  (match (raise level/low)
    (low (println "low"))
    (high (println "high"))))
```

Or return the matched value, which is that variant in this arm:

```lisp
(defenum level
  low
  high)

(defn raise (l)
  (match l (low level/high) (high l)))

(defn main ()
  (match (raise level/low)
    (low (println "low"))
    (high (println "high"))))
```
