A named function passed as a value must fit the function type that receives it.
knave adjusts the function's parameters where it can: it adds a borrow where the
expected type passes an owned value, copies out a small `Copy` value that the
expected type lends, accepts a function that takes a shared borrow where a `mut`
borrow is lent, drops a borrow that the function's parameter does not take, and
views a borrowed `vec` as a slice or a borrowed `string` as a `str`. None of
these turns this function's parameter into the expected one, as with a parameter
that changes its argument where the expected type lends a shared borrow, or one
that keeps its argument where the expected type lends a borrow.

The parameter modes of a function with no written types come from its body, so
the body decides the mismatch. knave reports this for a function passed as a
call argument, a `recur` argument or a positional constructor argument. The same
mismatch in a keyword constructor or a typed `local` reports `L0401`.

## Erroneous example

```knave
(type run-on
  (fn ((fn ((ref (vec i64))) unit)) unit))

(defn run-on (f) (f (vec 1 2)))

(defn change! (items) (push! items 3))

(defn main ()
  (run-on change!)
  (println "done"))
```

## Fixes

Pass a function that only reads its argument:

```knave
(type run-on
  (fn ((fn ((ref (vec i64))) unit)) unit))

(defn run-on (f) (f (vec 1 2)))

(defn show (items)
  (println (len items)))

(defn main ()
  (run-on show)
  (println "done"))
```

Or change the ownership in the signature, so the function may change the value:

```knave
(type run-on
  (fn ((fn ((mut (vec i64))) unit)) unit))

(defn run-on (f)
  (local items (vec 1 2))
  (f (mut items))
  (println (len items)))

(defn change! (items) (push! items 3))

(defn main ()
  (run-on change!)
  (println "done"))
```
