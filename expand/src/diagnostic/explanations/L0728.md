This error reports a path in the project file of a library fetched from git, or
of a library that such a library lists, that leads outside the library's
checkout, through `..`, an absolute path or a symbolic link. The path may be the
library's `:lib` file, the `:path` of a library it lists, a `:git` that names a
folder, or the `:path` of a crate. A checkout holds one commit of the
repository, and a path outside it is not part of that commit. A `:git` URL of
another machine names no path, so it never reports this error. A library that a
git library lists by `:path` keeps that checkout's bounds, and one that it lists
by `:git` takes the bounds of its own checkout.

`knave check`, `types`, `lint`, `expand`, `emit`, `build`, `run`, `test`,
`task`, `eval`, `repl`, `doc --write`, `add` and `remove` report it. `knave fmt`
fetches nothing: it reports it as a warning only for a checkout already in the
cache, and lays out the files all the same.

## Described example

The explanation tests cannot make a git repository, so they run no example
here. A library `hints`, fetched with `:git` and `:rev`, holds this project
file, and a project lists `hints`:

```text
(defproject hints (libraries (other :path "../other")))
```

`../other` leaves the checkout of `hints`, so the project reports this error at
`other`.

## Fixes

The library's authors can move what the path names into the checkout and name
it with a relative path that stays inside, or list the other library by a
`:git` URL and a `:rev`. A new `:rev` then names the fixed commit.
