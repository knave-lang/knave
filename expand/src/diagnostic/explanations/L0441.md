A number literal whose type is a type parameter of a `type` signature takes, at
each call, the type that the call gives the parameter, so it must suit each type
that the parameter's traits allow. This error reports such a literal when one of
those types has no room for its value, such as `char` with `(a partial-ord)`, an
integer type too small for the value, as `i8` for `300` or `u8` for `-1` with
`(n integer)`, an integer type for a float literal such as `0.5`, or `f32` for a
float too large for it, such as `1e39` with `(n float)`.

The check applies only to a parameter that a `type` signature declares. A
parameter with no trait reports `L0414` instead, and a literal whose type is a
number type that cannot hold it, or a float literal too large for `f64` whatever
its type, reports `L0406`.

## Erroneous example

```knave
(type add-bonus
  (where ((n integer)) (fn (n) n)))

(defn add-bonus (x) (+ x 300))

(defn main () (println (add-bonus 5)))
```

## Fixes

Name the type in the signature:

```knave
(type add-bonus (fn (i64) i64))

(defn add-bonus (x) (+ x 300))

(defn main () (println (add-bonus 5)))
```

Or take the bonus as an argument, so that the caller writes the literal:

```knave
(type add-bonus
  (where ((n integer)) (fn (n n) n)))

(defn add-bonus (x bonus) (+ x bonus))

(defn main ()
  (println (add-bonus 5 300)))
```
