A task's value is the result of the program that `knave task` builds for it,
as `main`'s is, so the compiler needs its whole type. This error reports a
task whose value is a `result` with a part of its type that nothing in the
task fixes. That part is either the error type, as in a body that ends with
`(ok (do))` or with a call of a function that ends that way, or the success
type when a trait bounds it, such as the target type of a `parse` whose value
the task returns in an `ok`.

A success type that nothing fixes or bounds, as in `(err (str "boom"))`, is
not an error: it becomes `unit`, as it does for `main`.

The compiler reads a task's type when it builds that task's runner, so
`knave task <name>` reports this error for the named task only, and
`knave check` with no file reports it for every task. `knave task` with no
name, and `knave check` of one file under `tasks/`, do not report it.

## Erroneous example

```lisp
;; knave task sweep
;; project.knv
(defproject chores)
;; src/main.knv
(defn main () (println "run a task with knave task"))
;; tasks/sweep.knv
(deftask sweep ()
  (println "sweeping")
  (ok (do)))
```

## Fixes

Drop the `ok`, so the task's value is `unit`:

```lisp
;; knave task sweep
;; project.knv
(defproject chores)
;; src/main.knv
(defn main () (println "run a task with knave task"))
;; tasks/sweep.knv
(deftask sweep ()
  (println "sweeping"))
```

Or return an `err` with a string on another branch, which fixes the error
type:

```lisp
;; knave task sweep
;; project.knv
(defproject chores)
;; src/main.knv
(defn main () (println "run a task with knave task"))
;; tasks/sweep.knv
(deftask sweep (:dry false)
  (if dry
    (err (str "a dry run sweeps nothing"))
    (do
      (println "sweeping")
      (ok (do)))))
```
