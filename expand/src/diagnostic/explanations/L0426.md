The compiler reads a `with` form, such as `(with string str)`, as one entry of
the types that a `rust-trait`, or a `deftrait`'s `(rust "Path")` clause, lists,
where `(with string str)` stands for `String: PartialEq<str>`. This error
reports a `with` that the compiler meets while it reads a type, such as a
parameter in a `type` signature, an enum payload, or the type of a `the` form. A
`with` nested inside another type, such as `(vec (with i64 i64))`, reports it
too, even inside an entry of a `deftrait`.

To say that a value can be compared with a second type, write a bound with that
type in a `where`, as in `(a (partial-eq i64))`.

## Erroneous example

```knave
(type matches (fn ((with i64 i64) i64) bool))

(defn matches (left right) (= left right))

(defn main () (println (matches 1 1)))
```

## Fixes

Name the parameter's own type:

```knave
(type matches (fn (i64 i64) bool))

(defn matches (left right) (= left right))

(defn main () (println (matches 1 1)))
```

Or take any type that compares with an `i64`, through a bound in a `where`:

```knave
(type matches (where ((a (partial-eq i64))) (fn (a i64) bool)))

(defn matches (left right) (= left right))

(defn main () (println (matches 1 1)))
```
