Each value gets one concrete type in the emitted Rust. This error reports a
value whose type, or a part of whose type, nothing in the program fixes by the
end of checking. Examples are the element type of a `(vec)` that nothing adds to
or reads as a known type, the payload type of `none`, and the target type of
`parse`. An unused `let`, a value passed to a parameter that ignores it, and an
unused parameter of a closure report it too. `main` reports it when it returns a
`result` with an open part, such as the error type of `(ok 5)`. A function whose
bound names a type that no argument or result holds reports it at a call,
because no call fixes that type.

A field read or a struct update on a value whose type is still unknown at that
point finds the struct by the field's name. It reports this error when no
struct, or more than one struct, declares that field, or for an update, every
field that it names. A `type` signature that names the struct fixes the type. An
integer literal's type stays unknown until something fixes it, so `(:x n)` after
`(let (n 5) ...)` reports this error too when no struct, or more than one,
declares `:x`.

## Erroneous example

```knave
(defn main ()
  (let (names (vec))
    (println (len names))))
```

## Fixes

State the element type in a `the` form:

```knave
(defn main ()
  (let (names (the (vec string) (vec)))
    (println (len names))))
```

Or give the vector an element, which fixes its type:

```knave
(defn main ()
  (let (names (vec "ana"))
    (println (len names))))
```
