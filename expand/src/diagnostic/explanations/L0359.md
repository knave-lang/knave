`deftask` defines a command of a project, which `knave task` runs, and a project
keeps its tasks in the `tasks` directory at its root. This error reports a
`deftask` in any other file, such as a file that `knave check` or `knave run`
reads on its own, even one inside a folder named `tasks`, as well as the entry
module of a project and every module it uses outside `tasks`, such as a helper
under `src`. A module under `tasks` that a task file uses but that the task tree
does not hold as a task file reports it too, with a label and a help for the
reason: a file that loads through a library whose folder lies under `tasks`, as
`(use hints)` with `(hints :path "tasks/lib")`, should be used by its path from
`tasks`; a file in a hidden folder, such as `tasks/.shared/helpers.knv`, which
the task tree skips, should move out of that folder; a file named `project.knv`,
which the task tree also skips, should be renamed; and a task file that another
file uses by a different path, as `(use ./more)`, should be used by its path
from `tasks`.

The compiler checks the task's shape and its name first, so a `deftask` with a
name that is not kebab-case reports `L0357` instead, wherever it lies, and one
with a keyword for its name reports `L0301`.

## Erroneous example

```knave
(deftask greet () (println "hello"))

(defn main () (greet))
```

## Fixes

Write the code as a function that `main` calls:

```knave
(defn greet () (println "hello"))

(defn main () (greet))
```
