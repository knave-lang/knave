The compiler checks a program and writes it as Rust, and rustc then compiles
that Rust. This error carries a message of rustc's that came without an error
code. A message of rustc's that has a code keeps rustc's code instead, so a
missing method reports `E0599`, a borrow conflict reports `E0502`, and a program
that builds a struct whose field holds the struct in an `option` reports
`E0391`. Messages without a code include Rust syntax errors in the text of a
`rust` form and some lifetime errors of rustc's borrow checker, such as a method
of an `impl` that returns a `str` field of a by-value `self` through a closure,
beside a `(ref str)` parameter.

The check and the emitter pass such a program, so the error shows only when a
command such as `knave build` or `knave run` compiles it. Where the compiler can
map rustc's place back to the source, the error points there, and the message
uses the program's own names.

When rustc stops without any error message that the compiler can read, such as
when rustc crashes, a program built by rustc directly rather than through Cargo
reports this error too, with rustc's output as a note.

## Erroneous example

```lisp
(def bump
  (rust "{0} + + 1" (fn (i64) i64)))

(defn main () (println (bump 1)))
```

## Fixes

Write Rust that parses in the text of the `rust` form:

```lisp
(def bump
  (rust "{0} + 1" (fn (i64) i64)))

(defn main () (println (bump 1)))
```

Or write the function in the language instead of in Rust:

```lisp
(defn bump (x) (+ x 1))

(defn main () (println (bump 1)))
```
