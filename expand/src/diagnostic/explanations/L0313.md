In macro code, `if` takes its branch from the values `true` and `false` alone.
This error reports an `if` in macro code whose test evaluates to any other
value, such as a number, a string or a list. The prelude forms that expand to
`if`, such as `when`, `cond`, `and` and `or`, test their conditions the same
way, except that `and` and `or` return their last operand without testing it.
The compiler finds this only when the `if` runs, so a branch that no macro call
takes reports nothing.

`bool-not` given a value other than a boolean reports `L0303` instead, and an
`if` in program code whose test is not a `bool` reports `L0401`.

## Erroneous example

```knave
(use code len prepend)

(defmacro print-all (items)
  (if (len items)
    (prepend (quote println) items)
    (quote (println "nothing"))))

(defn main () (print-all ("a" "b")))
```

## Fixes

Test the list with `empty?`, which returns a boolean:

```knave
(use code empty? prepend)

(defmacro print-all (items)
  (if (empty? items)
    (quote (println "nothing"))
    (prepend (quote println) items)))

(defn main () (print-all ("a" "b")))
```
