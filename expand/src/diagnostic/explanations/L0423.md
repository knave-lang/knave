A written `derive` lists a struct's or an enum's traits exactly. The compiler
can give a struct a trait only when every field's type implements the trait,
and an enum only when every variant's payload types do. This error reports a
listed trait that some field or payload type does not implement. A trait that a
listed trait brings counts too: `ord` brings `eq`, so `ord` on a struct with an
`f64` field reports `eq` there as well as `ord`.

Examples of such types are `string`, which is not `copy`, and `f64`, which is
not `eq` or `hash`. A function type, such as `(fn () i64)`, implements only
`clone`, `copy` and `debug` among these traits, so it refuses `partial-eq` or
`show`. A field whose type is another struct counts with that struct's own
traits, inferred or written, so a struct with an `f64` field gives a struct that
holds it no `hash`. A field whose type is a type parameter of the struct itself
accepts every trait.

Without a written `derive`, the compiler leaves out each trait that a field
refuses and reports nothing at the definition. A use that needs that trait then
reports `L0404`.

## Erroneous example

```knave
(defstruct reading :value f64)

(derive reading ord)

(defn main ()
  (let (low (->reading :value 1.5)
        high (->reading :value 2.5))
    (println (< low high))))
```

## Fixes

List `partial-ord`, which `f64` implements, in place of `ord`:

```knave
(defstruct reading :value f64)

(derive reading partial-ord)

(defn main ()
  (let (low (->reading :value 1.5)
        high (->reading :value 2.5))
    (println (< low high))))
```

Or store the reading in tenths, as an `i64`, which implements `ord`:

```knave
(defstruct reading :tenths i64)

(derive reading ord)

(defn main ()
  (let (low (->reading :tenths 15)
        high (->reading :tenths 25))
    (println (< low high))))
```
