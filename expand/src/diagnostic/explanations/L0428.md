A `try` hands the failure of its value to the caller of the enclosing function,
the innermost `defn` or `fn` around it. A `try` of an option returns `none`
early, and a `try` of a result returns its error early, so each needs a function
whose own result is of the same kind. This error reports a `try` whose function
already has a result of another kind, such as a `try` of a result in a function
that returns an option, a `try` of an option in a function that returns a
result, or any `try` in a function that returns an `i64`.

The function's result is known at the `try` when a `type` signature states it,
when the `fn` has an expected type, such as inside `the` or as an argument of a
function with a signature, or when an earlier `try`, or earlier code that gives
the function's result, such as a `match` arm, fixed it. When nothing has fixed
the result yet, the `try` sets it, and the body that disagrees reports `L0401`
instead. A `try` of a result whose error differs from the function's error
reports `L0437`.

## Erroneous example

```knave
(type double (fn ((ref str)) (option i64)))

(defn double (text) (some (* 2 (try (parse text)))))

(defn main () (println (unwrap-or (double "21") 0)))
```

## Fixes

Declare `double` with a result type, whose error is the error of `parse`:

```knave
(type double (fn ((ref str)) (result i64 (parse-error i64))))

(defn double (text) (ok (* 2 (try (parse text)))))

(defn main () (println (unwrap-ok (double "21"))))
```

Or keep the option type, and turn the result into an option with `match`:

```knave
(type double (fn ((ref str)) (option i64)))

(defn double (text)
  (match (parse text)
    ((ok number) (some (* 2 number)))
    ((err _) none)))

(defn main () (println (unwrap-or (double "21") 0)))
```
