A macro's code runs while the compiler expands the module, so each macro and
each `def` that macro code reads gets its value at compile time. This error
reports a cycle among compile-time values, such as a macro whose body calls the
same macro, a function that a macro's body calls and that calls the macro in
turn, a `def` whose value is a call of a macro whose body reads that `def`, or a
`def` that macro code reads and whose value is its own name or the name of a
`def` that names it back. A cycle of `def` names that no macro code reads is not
this error.

## Erroneous example

```knave
(use code empty? first rest)

(defmacro sum-of (items ...)
  (if (empty? items)
    (quote 0)
    (template (+ (unquote (first items))
                 (unquote (sum-of (rest items)))))))

(defn main () (println (sum-of 1 2 3)))
```

## Fixes

Put the recursive call inside the template, so it expands after this call:

```knave
(use code empty? first rest)

(defmacro sum-of (items ...)
  (if (empty? items)
    (quote 0)
    (template (+ (unquote (first items))
                 (sum-of (splice (rest items)))))))

(defn main () (println (sum-of 1 2 3)))
```
