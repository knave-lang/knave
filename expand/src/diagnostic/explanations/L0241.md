An `impl` holds one definition for each method that its trait lists, and
nothing else. A method in the `impl` whose name is missing from the trait's
list is this error. The rule is the same for a trait written with `trait` or
`deftrait` and for a prelude trait such as `display`.

When the misnamed method was meant to be one the trait requires, the `impl`
also lacks that method, which reports `L0239` at the implementor, above this
error. A method that the `impl` defines twice is `L0240`.

## Erroneous example

```lisp
(defstruct circle :radius f64)

(deftrait shape
  (area (fn ((ref self)) f64)))

(impl shape circle
  (area (c) (* 3.14 (:radius c) (:radius c)))
  (perimeter (c) (* 6.28 (:radius c))))

(defn main ()
  (println (area (->circle :radius 1.0))))
```

## Fixes

List `perimeter` in `shape` too, so that every implementor writes it:

```lisp
(defstruct circle :radius f64)

(deftrait shape
  (area (fn ((ref self)) f64))
  (perimeter (fn ((ref self)) f64)))

(impl shape circle
  (area (c) (* 3.14 (:radius c) (:radius c)))
  (perimeter (c) (* 6.28 (:radius c))))

(defn main ()
  (let (unit (->circle :radius 1.0))
    (println (area unit))
    (println (perimeter unit))))
```

Make the method a function of its own, outside the `impl`:

```lisp
(defstruct circle :radius f64)

(deftrait shape
  (area (fn ((ref self)) f64)))

(impl shape circle
  (area (c) (* 3.14 (:radius c) (:radius c))))

(type perimeter (fn ((ref circle)) f64))

(defn perimeter (c) (* 6.28 (:radius c)))

(defn main ()
  (let (unit (->circle :radius 1.0))
    (println (area unit))
    (println (perimeter unit))))
```
