A clause of a `rust` form replaces the template's Rust text for some types, and
every check before emission reads the template alone. So the compiler compares
each placeholder of the clause with the same placeholder of the template, from
the lowest number up, and then compares the two texts as a whole. This error
reports the first difference among these:

- one text uses a placeholder that the other leaves out, such as `{1}` in
  `count({0}, {1})` against `measure({0})`, or `count()` against `measure({0})`
- one text writes the placeholder a different number of times, or with a
  different marker, such as `{&0}` or `{owned 0}` against `{0}`
- one text starts with a method call on the placeholder, as `{0}.count()`
- one text indexes the placeholder, as `{0}[0]`
- one text dereferences the placeholder, as `*{0}`
- one text calls the placeholder, as `{0}(1)`, and the other does not, or calls
  it with other arguments
- one text makes the placeholder an operand of an operator, as `{0} + 1`, and
  the other does not
- the clause calls a function or a macro and the template does not, as
  `{0}.len()` against `{0}.len`, or the other way round

A malformed placeholder in a clause reports `L0218`, and a named placeholder
that names no type parameter reports `L0221`. Both are checked first.

## Erroneous example

```knave
(def larger
  (rust "std::cmp::max({0}, {1})"
    (where ((a ord)) (fn (a a) a))
    (i64 "{0}.max({1})")))

(defn main ()
  (println (larger 3 5)))
```

## Fixes

Write the clause as a path call with both arguments, as the template is:

```knave
(def larger
  (rust "std::cmp::max({0}, {1})"
    (where ((a ord)) (fn (a a) a))
    (i64 "i64::max({0}, {1})")))

(defn main ()
  (println (larger 3 5)))
```
