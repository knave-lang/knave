Each arm of a `match` starts with a pattern, and a variant or struct pattern
holds a pattern for each part. This code reports a pattern, at the top of an arm
or nested inside another pattern, that has one of three shapes:

- a list whose head is not a symbol, such as `(0 radius)` or `()`;
- a list whose head names no variant or struct in scope, such as `(square side)`
  when no enum declares `square`, or `(+ value)`. A variant of an enum from
  another module counts as unknown when the `use` leaves its enum out;
- the qualified name of a variant that carries a payload, written alone, such as
  `shape/circle`, which leaves out the patterns for its payload.

The patterns in the binding list of `let-match` follow the same rules. A bare
name such as `circle` or `some` is no error: it binds a new variable that
matches every value, so the arms after it never run.

## Erroneous example

```knave
(defenum shape (circle f64) point)

(defn area (s)
  (match s
    ((square side) (* side side))
    (_ 0.0)))

(defn main ()
  (println (area (shape/circle 2.0))))
```

## Fixes

Name a variant of the enum, with one pattern for each part of its payload:

```knave
(defenum shape (circle f64) point)

(defn area (s)
  (match s
    ((circle radius) (* 3.0 radius radius))
    (_ 0.0)))

(defn main ()
  (println (area (shape/circle 2.0))))
```

When the enum needs the missing variant, declare it:

```knave
(defenum shape (circle f64) (square f64) point)

(defn area (s)
  (match s
    ((square side) (* side side))
    (_ 0.0)))

(defn main ()
  (println (area (shape/square 2.0))))
```
