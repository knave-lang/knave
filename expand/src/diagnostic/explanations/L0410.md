A field read, such as `(:x value)` or `(field value x)`, and a struct update,
such as `assoc` with a keyword key, work on a struct. This error reports one
whose value has a known type that is not a struct, such as a number, a string,
a `bool`, a vector or an enum, even an enum whose cases have named fields. A
read looks through borrows, so `(:x p)` works when `p` is a `(ref point)`.

An update moves the other fields of its base into the new struct, so it reports
this error when its base is a borrow of a struct, such as a parameter of type
`(ref point)` or an element that `at` reads.

A value whose type is a type parameter with `has` bounds reads only the fields
those bounds name, so this error reports a read of any other field and names the
fields the bounds allow. It also reports an update of such a value, since a
`has` bound reads a field and cannot build the struct.

A read whose value is an integer or float literal that nothing has fixed
reports this error too, before any struct counts, and names the literal's
default type, `int` or `float`, because no struct is a number. When the value's
type is otherwise still unknown, a read reports `L0407`, or `L0408` when no
struct declares the field.

## Erroneous example

```knave
(defstruct point
  :x int
  :y int)

(defn main ()
  (let (points (vec (->point 1 2) (->point 3 4)))
    (println (:x points))))
```

## Fixes

Read the field of one element:

```knave
(defstruct point
  :x int
  :y int)

(defn main ()
  (let (points (vec (->point 1 2) (->point 3 4)))
    (println (:x (at points 0)))))
```

Or read the field of each element:

```knave
(defstruct point
  :x int
  :y int)

(defn main ()
  (let (points (vec (->point 1 2) (->point 3 4)))
    (println (sum (map (iter points) :x)))))
```
