The template of a `rust` form holds placeholders that the compiler fills when
it writes the Rust: `{0}`, `{1}` and so on take a call's arguments by position,
and `{a}` takes the type that the `where` binder `a` stands for at that use.
This error reports a template that the compiler cannot fill at a use that the
program reaches from `main`.

A numbered placeholder reports it when its number is at least the number of
parameters in the form's function type, such as `{1}` in a template of type
`(fn (i64) i64)`, or `{0}` in a template whose type is not a function. This
holds when the program calls the template, passes it as a value, or calls a
`rust` form where it is written. A type placeholder reports it when its binder
takes no type at the use, such as a `where` binder that the function type does
not mention, or any binder of a `rust` form written in place of a call's
function. A `rust` form with clauses reports it unless it is the value of a
`def`, such as one called where it is written or bound by `let`.

`knave check` reports none of these. A template in a `def` that `main` never
reaches reports nothing. A placeholder without its closing brace reports
`L0218`, a type placeholder that names no `where` binder reports `L0221`, and a
`rust-type` placeholder past the type's parameters reports `L0225`, all from
`knave check`.

## Erroneous example

```lisp
(def add (rust "{0} + {1}" (fn (i64) i64)))

(defn main () (println (add 1)))
```

## Fixes

Give the function type a parameter for each placeholder:

```lisp
(def add (rust "{0} + {1}" (fn (i64 i64) i64)))

(defn main () (println (add 1 2)))
```

Or write the second operand into the template:

```lisp
(def add-one (rust "{0} + 1" (fn (i64) i64)))

(defn main () (println (add-one 1)))
```
