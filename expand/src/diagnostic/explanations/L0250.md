The file `project.knv` at a project's root describes the project, its name,
entry and libraries, so a program's module path `project` stays free of code. A
`use` of the bare path `project` in a program's file reports this error, whether
or not a project exists. So does a `use` of a library named `project`: the
project file accepts that name, but no program can import the library's `:lib`
module, though a path such as `project/other` still reaches its other modules.
In a library's file, the path `project` names the library's own module
`project`. A longer path that starts with `project/`, such as
`project/settings`, is an ordinary module path.

## Erroneous example

```knave
(use project greeting)

(defn main () (println greeting))
```

## Fixes

Keep the definition in a module of another name, or in the file that uses it:

```knave
(def greeting "hi")

(defn main () (println greeting))
```
