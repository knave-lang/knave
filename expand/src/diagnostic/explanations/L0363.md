Macro code runs while the compiler expands the program, and every macro call
inside one top-level form shares one budget of steps, 30,000,000 by default.
This error reports the call that spends past that budget, so a macro that never
stops ends with an error. The steps measure the work that the macro code does,
such as each function call and each built-in call.

The budget covers the work that a macro call starts, such as a function that the
macro calls, a compile-time `def` that the macro reads, and a call made through
`expand-call`. Two calls in one top-level form add their steps together, so the
second can pass the budget although each fits on its own, while a call in
another top-level form starts a fresh budget.

The prelude form `(with-macro-steps count form)` gives its top-level form a
budget of `count` steps, as the example below does so that it stops quickly. A
`def` whose value never stops, when no macro reads it, reports `L0407` instead.

## Erroneous example

```lisp
(use code number-add value-eq)

(def count-down
  (fn (remaining)
    (if (value-eq remaining 0)
      remaining
      (recur (number-add remaining 1)))))

(defmacro settled (start) (count-down start))

(with-macro-steps 100000
  (defn main () (println (settled 3))))
```

## Fixes

Make the loop reach the value that ends it:

```lisp
(use code number-sub value-eq)

(def count-down
  (fn (remaining)
    (if (value-eq remaining 0)
      remaining
      (recur (number-sub remaining 1)))))

(defmacro settled (start) (count-down start))

(defn main () (println (settled 3)))
```

Or do the work in a function that runs with the program:

```lisp
(defn settled (start)
  (if (= start 0)
    start
    (settled (- start 1))))

(defn main () (println (settled 3)))
```
