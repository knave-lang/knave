A trait that `rust-trait` binds, or that `deftrait` binds with a `rust` clause,
declares an associated type with `(associated (name owner) "RustName")`. Each
implementor entry of the trait then states every declared associated type with a
`(name type)` clause at the end of a `where` entry, as in `(where () i64
(negative i64))`. This error reports an entry that lacks the clause for one of
them, such as a bare type like `i64`, a `(with f64 f64)` entry, or a `where`
entry that states one of two declared types. The compiler checks a trait's
entries in order and stops at the first that fails, so a trait reports one
error.

Within one entry, a clause that names a type the trait does not declare reports
`L0452` instead, which the compiler checks first.

## Erroneous example

```knave
(deftrait negated
  (rust "std::ops::Neg")
  (associated (negative value) "Output")
  (where () i64))

(type flip (fn (i64) (negative i64)))

(defn flip (n) (- 0 n))

(defn main () (println (flip 5)))
```

## Fixes

Write `(negative i64)` as the last part of the `i64` entry:

```knave
(deftrait negated
  (rust "std::ops::Neg")
  (associated (negative value) "Output")
  (where () i64 (negative i64)))

(type flip (fn (i64) (negative i64)))

(defn flip (n) (- 0 n))

(defn main () (println (flip 5)))
```
