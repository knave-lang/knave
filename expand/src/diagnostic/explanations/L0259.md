A program may bind a kernel type's name in the type namespace: a struct, an
enum, a trait or a Rust type named `float`, a `where` binder such as
`(where (int) ...)`, or a type parameter on a struct's or an enum's name. The
binding hides the kernel type in its scope, so `float` written there names the
program's type, while a type the compiler prints as `float` is still the kernel
type. A mismatch can then read ``expected `float`, found `float` ``, and an
`infer` text no longer pastes into a `type` signature.

This warning reports each such binding under any kernel type's name, such as
`int`, `i64`, `float`, `f64` or `string`, and each `use` that imports one. A
`use` that imports the kernel type itself reports nothing.

## Erroneous example

```knave
(defstruct float
  :whole i32
  :fraction u32)

(defn main ()
  (println (:whole (->float 3 14))))
```

## Fixes

Give the type a name of its own:

```knave
(defstruct decimal
  :whole i32
  :fraction u32)

(defn main ()
  (println (:whole (->decimal 3 14))))
```
