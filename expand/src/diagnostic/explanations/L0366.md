A `rust-trait` may name another trait in an `includes` clause. Every
implementor of the included trait then implements this trait too, beside the
rows this trait lists, and a function generic over this trait takes the
included trait instead. The prelude's `printable` includes `display`: every
`display` type prints, and so does a `duration`, which formats with `{:?}`,
while a function that prints its parameter takes `display`, because Rust's `{}`
in a generic function needs `std::fmt::Display`.

The included trait must bind the same Rust trait, so that the emitted bound of
a generic function is the one its own trait names. This error reports an
`includes` clause whose trait binds another Rust trait, or no Rust trait at all.

## Erroneous example

```knave
(rust-trait shown "std::fmt::Debug")

(rust-trait printed "std::fmt::Display"
  (includes shown)
  bool)
```

## Fixes

Name a trait that binds the same Rust trait:

```knave
(rust-trait printed "std::fmt::Display"
  (includes display)
  bool)

(type framed
  (where ((a printed))
    (fn ((ref a)) string)))

(defn framed (value) (str "[" value "]"))

(defn main () (println (framed true)))
```
