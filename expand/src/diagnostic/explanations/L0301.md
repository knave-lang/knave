A macro reports this error when its code calls `fail` from the `code` module
with a description that names no other code. The macro's author writes the
message, the help and the labels, and the error points at the form that the
macro passes to `fail`, such as one of the call's arguments. Many prelude
macros refuse their input this way, such as `defstruct` given a field such as
`x` where it takes `:x`, or a `defrule` macro called with a form that none of
its rules matches. A `fail` whose description names a code with `:code`, such
as `(:code expansion-too-deep)`, reports that code instead.

Read the macro's message and help, then change the call to give the macro the
input it takes.

## Erroneous example

```knave
(defstruct point
  x i64 y i64)

(defn main ()
  (println (:x (->point :x 1 :y 2))))
```

## Fixes

Give `defstruct` its input in the shape it takes, with each field as a keyword:

```knave
(defstruct point
  :x i64
  :y i64)

(defn main ()
  (println (:x (->point :x 1 :y 2))))
```
