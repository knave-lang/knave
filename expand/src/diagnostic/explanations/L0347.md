The kernel's `enum` spells named fields as a `struct` list inside the variant,
such as `(labeled (struct (text string)))`. In `defenum`, a variant with named
fields lists `:field type` pairs instead, as `(point :x i64 :y i64)` does. This
error reports a list headed by `struct` among the items of a variant whose
first item is not a keyword, at any position, such as
`(labeled i64 (struct (text string)))`, and whatever the `struct` list holds.
The items are checked in order, so a keyword before the `struct` list reports
`L0348` instead.

In a variant whose first item is a keyword, a `struct` list in the place of a
type reads as a type named `struct`, `L0201`, and in the place of a field
keyword it reports `L0348`.

## Erroneous example

```knave
(defenum shape
  (labeled (struct (text string) (size f64)))
  dot)

(defn main ()
  (match (shape/labeled (str "note") 2.0)
    ((labeled text _) (println text))
    (dot (println "dot"))))
```

## Fixes

Write each field as a keyword and a type:

```knave
(defenum shape
  (labeled :text string :size f64)
  dot)

(defn main ()
  (match (shape/labeled (str "note") 2.0)
    ((labeled text _) (println text))
    (dot (println "dot"))))
```
