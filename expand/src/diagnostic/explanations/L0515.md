A function that changes an unannotated parameter, such as with `set!`, changes
the caller's own value: knave passes that argument as a mutable borrow. Used as
a value instead of called by name, the function goes where the receiving type
passes each argument by value. knave would then give the function a fresh copy
of the argument, so a change to a `Copy` value, such as a number, would reach
only that copy, and the caller would never see it.

knave reports this when such a function becomes one of these values: an argument
to a call or to `recur`, the value of a struct field or of a constructor
argument that fills a field, and a `local` bound to the function. It does not
report a parameter whose type a signature writes, a value that is not `Copy`,
which the caller gives up anyway, or a receiving type that already takes `(mut
...)`.

## Erroneous example

```lisp
(defn bump! (x) (set! x (+ x 1)))

(defn apply-to (f n) (f n))

(defn main ()
  (local total 1)
  (apply-to bump! total)
  (println total))
```

## Fixes

Write the receiving function's type with `mut`, so the caller's value changes:

```lisp
(defn bump! (x) (set! x (+ x 1)))

(type apply-to! (fn ((fn ((mut i64)) unit) (mut i64)) unit))
(defn apply-to! (f n) (f n))

(defn main ()
  (local total 1)
  (apply-to! bump! (mut total))
  (println total))
```

Or, to change a copy on purpose, start the body with a local of the same name:

```lisp
(defn bump! (x) (local x x) (set! x (+ x 1)) (println x))

(defn apply-to (f n) (f n))

(defn main ()
  (local total 1)
  (apply-to bump! total)
  (println total))
```
