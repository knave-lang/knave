Some commands read every `.knv` file in a folder as a module, such as `knave
test` given a folder or none, `knave task`, `knave check` in a project, which
reads `tasks/`, and `knave doc --write`, which reads the source root. A file's
module path is its path without `.knv` from the folder the command reads, except
that `knave test` in a project takes it from the source root when the file lies
inside it. This error reports each such file whose module path is `prelude`,
`kernel` or `code`, or starts with `prelude/`, such as `tests/kernel.knv`,
`tasks/code.knv` or `src/prelude/extra.knv`.

`knave check`, `knave build` and `knave run` do not read the source root this
way, so they report nothing for `src/kernel.knv` or `src/prelude/extra.knv`, and
a `(use prelude/extra ...)` reaches the program's `src/prelude/extra.knv`, but
loads it as a module of the prelude, which sees none of the prelude's names.
`knave test` given one file reads no folder and reports nothing either, and runs
none of the tests of a `tests/kernel.knv`.

## Erroneous example

```knave
;; knave test
;; project.knv
(defproject app)
;; src/main.knv
(defn main () (println (+ 1 1)))
;; tests/kernel.knv
(deftest adds (assert (= (+ 1 1) 2)))
```

## Fixes

Give the file a module path of the program's own, such as `arithmetic`:

```knave
;; knave test
;; project.knv
(defproject app)
;; src/main.knv
(defn main () (println (+ 1 1)))
;; tests/arithmetic.knv
(deftest adds (assert (= (+ 1 1) 2)))
```
