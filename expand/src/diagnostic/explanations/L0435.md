A `rust` clause right after an enum's name or its docstring, whether it holds a
path such as `"Option"` or a template such as `"({0}, {1})"`, makes the enum
stand for a type that Rust already defines. The program emits no definition for
such an enum, so it has nothing to attach a Rust `derive` attribute to.

This error reports a `derive` form whose type is such an enum, whatever traits
the form lists, even none. Each such `derive` form reports it. A `derive` of a
type that this module does not define as a `struct` or an enum, such as the
prelude's `option` or a type that `deftype` names, reports `L0237` instead.

## Erroneous example

```knave
(defenum (maybe value)
  (rust "Option" bare)
  (some value)
  none)

(derive maybe clone)

(defn main ()
  (match (maybe/some 3)
    ((some n) (println n))
    (none (println "none"))))
```

## Fixes

Remove the `derive` form, and keep the Rust type:

```knave
(defenum (maybe value)
  (rust "Option" bare)
  (some value)
  none)

(defn main ()
  (match (maybe/some 3)
    ((some n) (println n))
    (none (println "none"))))
```

Or remove the `rust` clause, so that the program defines the enum and the
`derive` form lists its traits:

```knave
(defenum (maybe value)
  (some value)
  none)

(derive maybe clone)

(defn main ()
  (match (maybe/some 3)
    ((some n) (println n))
    (none (println "none"))))
```
